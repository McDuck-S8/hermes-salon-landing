Вот практический чек-лист для запуска pSEO на 10K+ страниц — без воды, только схемы, код и метрики.

---

**1. Проектирование шаблона (JSON-схема)**
Вместо жесткого HTML — используйте **компонентный конструктор** на базе Mustache/Nunjucks:
```json
{
  "slug": "{{ city|slug }}/{{ service|slug }}",
  "h1": "{{ service }} in {{ city }}",
  "hero": "{{ images.pick('city_hero') }}",
  "sections": ["benefits", "pricing_chart", "map", "faq"],
  "faq": { "q": "{{ query }}", "a": "{{ gpt_summary }}" }
}
```
**Логика:** каждый блок имеет условие `show_if: field.count > 0` — это защита от дырок в данных.

**2. Источники данных (3 слоя)**
- **API 1-го уровня:** Google Places / Yelp (рейтинг, часы работы), OpenWeather (погода для локального контента).
- **БД:** PostgreSQL с кешем (Redis) — храним сырые данные, а не готовые страницы.
- **Скрапинг (крайний случай):** используем `Scrapy` + `Playwright` для конкурентов, но парсим только структуру (заголовки, список услуг), а не текст — чтобы не нарушать copyright.
- **CDC (Change Data Capture):** каждую ночь пересобираем только страницы, где изменился рейтинг или цена.

**3. Контроль качества контента (автоматизация)**
В CI/CD добавляем 3 валидатора:
- **Уникальность n-грамм** — проверка на пересечение с топ-10 страниц сайта (алерт если совпадение > 60%).
- **Тональность** — через `VADER` или `Cohere` классификатор: если нейтральная, добавляем эмоциональный хук в интро.
- **Факт-чекинг:** сверяем упомянутые цифры (цены, расстояния) с первичным API — расхождение > 5% блокирует публикацию.

**4. Индексация и приоритезация**
- **Sitemap-динамика:** генерируем 1 sitemap на 5K страниц, обновляем `lastmod` только при изменении контента.
- **Внутренний PageRank:** передаем вес через "hub-страницы" (категории), а на дочерние ставим `noindex` до появления первых органических ссылок.
- **Расписание:** для новых страниц — `index_now` API (Bing/Yandex), для старых — рекроллинг через Google Search Console раз в 2 недели.

**5. Борьба с дублями (канонический коллапс)**
Правило **"один смысл — один URL"**: 
- Если вариации (пагинация, сортировка) — добавляем параметр `?sort=` и закрываем его `noindex,follow`.
- Для географических пересечений (например, "Нью-Йорк" и "Манхэттен") используем **кросс-каноники**: на странице района указываем `canonical` на городскую, но оставляем свой уникальный блок "local_events".

**6. Инструменты и стек**
- **Генерация:** `Next.js` (ISR) или `Hugo` для статики.
- **Очередь задач:** `Celery` + `Redis` для построчной обработки (100 страниц/мин).
- **Мониторинг:** `Datadog` — трекер времени загрузки шаблона, `Sentry` — лог ошибок в данных.
- **SEO-метрики:** доля индексированного (порог > 85%), CTR в выдаче (срез по новым vs старым URL), процент страниц с нулевым трафиком > 30 дней — отправляем на доработку.

**7. Workflow (Day 1)**
```
06:00 — ETL: выгрузка из API → чистка (дубли по названию) → запись в БД
08:00 — Билд: рендер шаблона → проверка качества → генерация HTML
10:00 — Деплой: дифф между старым и новым контентом → push в CDN
12:00 — Пинг: отправка обновленных URL в Search Console API
00:00 — Отчет: рост позиций по топ-100 запросам, падение по "неиндексированным"
```

**Главный KPI:** скорость достижения первого места в "песочнице" (новый домен) — для этого первые 30 дней добавляем `noarchive` и наращиваем ссылочный скоринг через автоматический аутрич (HARO-подобные API).
