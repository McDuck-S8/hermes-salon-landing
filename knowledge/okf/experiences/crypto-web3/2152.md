# Блок 1. Чек-лист аудита смарт-контрактов (Smart Contract Audit Checklist)

Перед тем как положить хотя бы $100 в любой протокол, вы **обязаны** пройти по этому списку. Это ваш фильтр №1.

## 1.1. Базовый уровень безопасности (Безопасность кода)
- [ ] **Аудит от топ-3 фирм:** Проверьте, что аудит проводили **Trail of Bits**, **OpenZeppelin** или **CertiK**. Аудит от малоизвестной фирмы = отсутствие аудита.
- [ ] **Дата аудита:** Аудит должен быть проведен **после последнего обновления кода**. Если протокол обновлялся вчера, а аудит годовой давности — это красный флаг.
- [ ] **Наличие баг-баунти:** Активная программа на **Immunefi** с минимальной наградой $100,000+. Баг-баунти без реальных выплат = маркетинг.
- [ ] **Административные ключи (Admin Keys):** Есть ли мультисиг (Gnosis Safe)? Кто подписанты? Если подписантов меньше 5 и они неизвестны — протокол может быть скомпрометирован в любой момент.
- [ ] **Таймлоки (Timelocks):** Любое изменение параметров (например, комиссий) должно иметь задержку **минимум 24 часа**. Если изменяют мгновенно — бегите.
- [ ] **Отсутствие `selfdestruct`** в пользовательских контрактах — это позволяет убить контракт и забрать деньги.

## 1.2. Продвинутый уровень (Экономическая и ценовая безопасность)
- [ ] **Максимальный лимит на вывод (`withdraw limit`)**: Есть ли ограничение на сумму вывода за одну транзакцию? Если нет — одна ошибка может обнулить пул.
- [ ] **Оракулы (цены):** Используется ли **Chainlink** с децентрализованными узлами (а не один Uniswap V3, где ценой легко манипулировать через флеш-лоан)? Проверьте дельту между ценой оракула и биржевой ценой на CoinGecko — она должна быть < 3%.
- [ ] **Механизм экстренной паузы (Pausable):** Кто может остановить протокол? Если один человек — это централизация. Если голосование DAO — безопасно.

# Блок 2. Страхование депозитов (Insurance Protocols)

Страхование в DeFi — это **хедж против некатастрофических событий**. Вы страхуете не весь портфель, а только "токсичные" активы (новые протоколы, высокорисковые пулы).

## 2.1. Сравнение Nexus Mutual vs InsurAce (Практический выбор)

| Критерий | Nexus Mutual | InsurAce |
| :--- | :--- | :--- |
| **Модель** | Взаимное страхование (члены голосуют за каждую выплату) | Пул ликвидности с автоматической оценкой |
| **Покрытие** | Смарт-контракты, оракулы, валидаторы | Смарт-контракты, стейблкоины, займы |
| **Срок покрытия** | 30–365 дней (гибкий) | 7–180 дней |
| **Время выплаты** | Может занять **недели** (голосование) | **24–48 часов** (если подтверждено) |
| **Стоимость** | 2.5–7% от страховой суммы в год | ~2.5% за 30 дней |
| **Для кого** | Протоколы с высокой капитализацией (Aave, Compound) | Новые протоколы, стейблкоин-пулы |

**Практическое правило:**
- **Для стейблкоинов (USDC/USDT) в лендинге** → страхуйте в **InsurAce** (быстрая выплата).
- **Для LP-токенов (Uniswap, Curve)** → страхуйте в **Nexus Mutual** (там эксперты глубже анализируют риски).

## 2.2. Калькулятор оптимальной страховой суммы (Excel-шаблон)

Используйте эту формулу для расчета, какую долю портфеля страховать:

```
Сумма_страховки = min(Общий_депозит * 0.5, Общий_депозит * P_взлома * L)
```

Где:
- `P_взлома` — вероятность взлома за год (для Aave = 1%, для Curve = 3%, для нового протокола = 15% — тогда лучше не вкладывать).
- `L` — доля потерь при взломе (обычно 100%, если взломали контракт).

**Пример:** У вас $100,000 в Aave (P=1%). Сумма страховки = 100,000 * 0.01 * 1 = $1,000. Но вы страхуете **$50,000** (потому что формула дает минимум с 50%). Это стоит ~$3,500 в год.

# Блок 3. Модели аллокации портфеля (Risk Parity & Kelly Criterion)

Без модели распределения вы — игрок в казино. С моделью — управляющий активами.

## 3.1. Risk Parity (Паритет риска) — для консерваторов

**Суть:** Каждый актив вносит **равный вклад в общую волатильность** портфеля. Это более разумно, чем простой 50/50.

**Алгоритм:**
1. Рассчитайте 30-дневную волатильность (стандартное отклонение) для каждого актива в портфеле.
2. Вес актива = (1 / Волатильность_актива) / Σ(1 / Волатильность_всех)

**Пример (портфель: BTC, ETH, USDC):**
| Актив | Волатильность (годовая) | Вес (Risk Parity) |
| :--- | :--- | :--- |
| BTC | 60% | 33% |
| ETH | 70% | 28% |
| USDC | 1% | 39% |

> **Парадокс:** Стейблкоин (USDC) получает самый большой вес, потому что он "гасит" волатильность всего портфеля.

**Инструмент:** Код для расчета Risk Parity на Python:
```python
import numpy as np
from scipy.optimize import minimize

def risk_parity_weights(cov_matrix):
    n = len(cov_matrix)
    def objective(w):
        portfolio_var = w @ cov_matrix @ w
        risk_contrib = w * (cov_matrix @ w) / portfolio_var
        return np.sum((risk_contrib - 1/n)**2)
    constraints = ({'type': 'eq', 'fun': lambda w: np.sum(w) - 1})
    bounds = [(0, 1) for _ in range(n)]
    result = minimize(objective, np.ones(n)/n, bounds=bounds, constraints=constraints)
    return result.x

# Пример использования
cov_matrix = np.array([[0.36, 0.15, 0.01], [0.15, 0.49, 0.01], [0.01, 0.01, 0.0001]])
weights = risk_parity_weights(cov_matrix)
print(weights)  # [0.33, 0.28, 0.39]
```

## 3.2. Kelly Criterion (Критерий Келли) — для агрессивных стратегий

**Суть:** Определяет **оптимальный размер ставки** на основе вашего исторического преимущества.

**Формула полного Келли:**
```
f = (p * (b + 1) - 1) / b
```
Где:
- `p` = вероятность выигрыша (например, ваша стратегия срабатывает в 55% случаев).
- `b` = соотношение средней прибыли к среднему убытку (например, вы зарабатываете 20% в среднем, а теряете 10%, тогда b = 2).

**Пример:** p=0.55, b=2 → f = (0.55 * 3 - 1) / 2 = 0.325 (32.5% портфеля).

**⚠️ ВАЖНО:** Используйте **половинный Келли (Half-Kelly)**, умножив f на 0.5. Это снижает волатильность и защищает от разорения. В примере → 16.25%.

# Блок 4. План экстренной эвакуации (Emergency Exit Procedures)

Это ваш **аварийный люк**. Без него вы — заложник протокола.

## 4.1. Триггеры для немедленного вывода (Красные флаги):

1. **Технические:**
   - Газ (gas price) вырос в 5 раз за 1 час → возможна атака или перегрузка сети.
   - Аномальная активность по адресу контракта (например, кто-то начал выводить огромные суммы).
2. **Экономические:**
   - TVL (Total Value Locked) протокола упал на 30% за 6 часов — доверие потеряно.
   - APR упал в 2 раза — вероятно, протокол теряет доходность.
3. **Социальные:**
   - Основатели удалили твиты или молчат в Discord > 24 часов.
   - Появились слухи об эксплойте (даже если не подтверждены — выводите).

## 4.2. Пошаговая процедура (Алгоритм действий за 3 минуты):

1. **STEP 0 (Подготовка заранее):** На всех кошельках, которые работают с DeFi, **заранее одобрите (approve)** вывод токенов. Это сэкономит 1 транзакцию (и 2 минуты) в критический момент.
2. **STEP 1 (Отзыв ликвидности):** Зайдите в пул → Remove Liquidity (100%).
3. **STEP 2 (Конвертация в стейбл):** Через агрегатор (1inch или Paraswap) обменяйте все активы на USDC.
4. **STEP 3 (Мост на L1):** Если вы на L2 (Arbitrum/Optimism) — используйте официальный мост (или даже более быстрый, например, **deBridge**), чтобы перевести USDC обратно на Ethereum.
5. **STEP 4 (Холод):** Переведите USDC на аппаратный кошелек (Ledger) и не взаимодействуйте с сетью 48 часов (чтобы убедиться, что не было утечки ключей).

## 4.3. Готовый Telegram-бот для оповещения о газе (Python + Make.com)

```python
import requests
from web3 import Web3
import time

TELEGRAM_TOKEN = "YOUR_TOKEN"
CHAT_ID = "YOUR_CHAT_ID"
GAS_THRESHOLD = 150  # gwei

w3 = Web3(Web3.HTTPProvider('https://mainnet.infura.io/v3/YOUR_KEY'))

def send_alert(message):
    url = f"https://api.telegram.org/bot{TELEGRAM_TOKEN}/sendMessage"
    requests.post(url, json={'chat_id': CHAT_ID, 'text': message})

while True:
    gas_price = w3.eth.gas_price / 1e9  # конвертация в gwei
    if gas_price > GAS_THRESHOLD:
        send_alert(f"⚠️ ГАЗ ВЫШЕ {GAS_THRESHOLD} GWEI! Срочно выводите средства!")
    time.sleep(300)  # проверка каждые 5 минут
```

# Блок 5. Метрики риска (Risk Metrics Dashboard)

Создайте **Google Looker Studio** или **Dune Analytics** дашборд, который показывает эти 5 метрик в реальном времени:

| Метрика | Что отслеживает | Действие при красном уровне |
| :--- | :--- | :--- |
| **TVL протокола** | Доверие рынка | Падение на 20% за сутки → эвакуация 50% |
| **Объем торгов (24h)** | Ликвидность | Падение на 40% → эвакуация 100% |
| **Коэффициент залога** | Риск ликвидации вашей позиции | Приближение к 150% (для займов) → добавить залог или вывести |
| **Spread пула** | Манипуляции ценой | > 5% между ценой пула и рынком → эвакуация 100% |
| **Активные адреса** | Активность пользователей | Падение на 50% за неделю → эвакуация 50% |

## 5.1. Пример скрипта для сбора данных с Dune Analytics (API)

```python
import requests

DUNE_API_KEY = "YOUR_KEY"
QUERY_ID = 123456  # ID вашего запроса на Dune

def get_tvl(protocol):
    url = f"https://api.dune.com/api/v1/query/{QUERY_ID}/results"
    headers = {"x-dune-api-key": DUNE_API_KEY}
    response = requests.get(url, headers=headers)
    data = response.json()
    tvl = data['result']['rows'][0]['tvl_usd']
    return tvl

tvl_aave = get_tvl('aave')
print(f"TVL Aave: ${tvl_aave:,.0f}")
```

# Блок 7. Финальный чек-лист перед входом в любую позицию

Перед тем как нажать "Deposit", задайте себе 3 вопроса:

1. **"Могу ли я потерять 100% этой суммы и при этом нормально спать?"** Если нет — уменьшите позицию в 2 раза.
2. **"Если протокол заморозит вывод на 7 дней (как это было с Celsius), у меня есть кэш на жизнь?"** — Держите 6 месяцев расходов в фиате или USDC на холодном кошельке.
3. **"Моя стратегия работает, если APR упадет с 20% до 5%?"** — Если нет, то вы не инвестируете, а играете в лотерею.
