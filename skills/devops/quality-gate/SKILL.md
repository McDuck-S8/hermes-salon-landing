# Quality Gate

## Призначення
Автоматична верифікація HTML/CSS правок перед демонстрацією клієнту.
Запускається через `delegate_task` або напряму перед фінальною відповіддю.

**Quality Gate — обов'язковий крок. Це той самий "спеціаліст, який перевіряє всі косяки". Його запуск перед показом клієнту — не опція, а правило.**

## Тригер
Після будь-якої зміни HTML/CSS файлів (лендінг, сайт, демо).
Використовувати як фінальний крок перед відповіддю клієнту.

## Що перевіряє

### 1. Структура HTML
- HTML/head/body збалансовані
- main тег закритий
- Немає незакритих div-ів
- Кодування UTF-8

### 2. CSS
- Всі класи, що використовуються в HTML, визначені в CSS
- Немає дублікатів селекторів
- Media queries збалансовані
- Немає залишків старого CSS після видалення HTML-секцій

### 3. Ресурси
- Всі зображення мають alt текст
- Всі посилання не пусті (не href="#")
- Фото завантажуються (>10KB кожне)
- Немає битих посилань на внутрішні якорі (#price після видалення секції)

### 4. WCAG (мінімум AA)
- Skip link присутній
- focus-visible стилі є
- aria-hidden на емодзі
- for/id на формі (якщо є)
- Рольові атрибути (role="banner", role="navigation", role="main", role="contentinfo")
- Alt тексти описові (не "Salon", а "Салон краси Fargo")
- WCAG бейдж у футері

### 5. Повнота контенту (CRITICAL)
**Не покладатися тільки на структуру!** Перевіряти ЗМІСТ.

- ✅ Фото на місці — перевірити src шляхи, чи файли існують
- ✅ Галерея заповнена — не містить заглушок "(добавьте фото)"
- ✅ Секції не пусті — відгуки, контакти заповнені реальним контентом
- ✅ Немає дублювання — секції не повторюють одна одну
- ✅ Соцкнопки мають реальні посилання (не href="#")
- ✅ Кнопки не биті — всі #якорі вказують на існуючі секції
- ✅ Відповідність OSINT — чи всі дані з аналізу перенесені на сайт

### 6. Консистентність
- Всі зміни відповідають запиту клієнта
- Немає зайвих змін (scope creep)
- Код відповідає стилю проекту

## Формат виводу

```
=== QUALITY GATE REPORT ===
✅ Структура: passed/failed
✅ Ресурси: passed/failed  
✅ WCAG: passed/failed (N issues)
✅ Повнота контенту: passed/failed
✅ Консистентність: passed/failed

Деталі:
- [issue 1]: опис
- [issue 2]: опис

Вердикт: PASS / REWORK
```

Якщо VERDICT = REWORK — виправити через `delegate_task`, потім знову Quality Gate. Якщо PASS — показувати клієнту.

## Скрипт qa_check.py

```bash
python skills/devops/quality-gate/scripts/qa_check.py path/to/index.html
```

Перевіряє в один запуск:
- Збалансованість HTML-тегів
- Alt тексти на всіх зображеннях
- Пусті посилання (href="#" або "")
- WCAG: skip-link, focus-visible, рольові атрибути
- Форми: наявність `for=` на всіх label
- Повертає exit code 0 (PASS) або 1 (REWORK)

## Правила
- Якщо VERDICT = REWORK — виправити помилки і запустити знову
- Якщо VERDICT = PASS — можна показувати клієнту
- Quality Gate не змінює файли — тільки перевіряє
- **Запускати Quality Gate ОБОВ'ЯЗКОВО перед фінальною відповіддю клієнту**
- **Перевіряти: файловий шлях (чи той файл відкрив клієнт), дублікати секцій, фото (відкрити URL), відсутність WCAG**
- **Перевіряти зміст, не тільки структуру.** Якщо клієнт питає "а де фото?" — Quality Gate недопрацював.
- **Не видаляти контент без питання.** Якщо на сайті вже щось є — "там була причина". Виправити, не видаляти.
