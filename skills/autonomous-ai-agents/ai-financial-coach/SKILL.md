# AI Financial Coach — Arbitrage P&L Intelligence

Your CFO for CPA/arbitrage. Knows exactly which schemes make money and which 
burn budget.

## Core Mission

**Input**: Spend data, revenue data, campaign metadata  
**Output**: Actionable P&L per scheme, ROI rankings, budget reallocation 
recommendations, risk alerts

## What It Tracks

| Metric | Source | Formula |
|---|---|---|
| **Spend** | Tracker / ad platform API | Sum of clicks * CPC |
| **Revenue** | CPA network postbacks / API | Sum of confirmed conversions * payout |
| **Net Profit** | Calculated | Revenue - Spend |
| **ROI** | Calculated | (Revenue - Spend) / Spend * 100% |
| **CPA** | Calculated | Spend / Confirmed Conversions |
| **EPC** | Calculated | Revenue / Clicks |
| **Approval Rate** | Network API | Approved / Total Conversions |
| **Cash Flow Gap** | Calculated | Days from spend to payout |

## Skills

### 1. Daily P&L Reconciliation
```
GOAL: Reconcile yesterday's spend vs revenue across all active schemes
CONTEXT: finance-core ledger + network APIs + tracker exports
ACCEPTANCE:
  - Every active campaign has: spend, revenue, profit, ROI
  - Discrepancies >5% flagged
  - Cash flow projection for next 7/14/30 days
FORMAT: JSON per campaign + summary table
```

### 2. Scheme Viability Scoring
```
GOAL: Score each scheme 1-10 on profitability sustainability
CONTEXT: 14-30 days of historical data per scheme
CRITERIA:
  - ROI stability (std dev of daily ROI)
  - Approval rate trend
  - Payout reliability (network history)
  - Scalability ceiling (offer caps, geo saturation)
  - Traffic source diversification
FORMAT: Ranked list with scores and "scale / maintain / kill" tags
```

### 3. Budget Allocation Optimizer
```
GOAL: Recommend tomorrow's budget distribution
CONTEXT: Current balances, scheme scores, cash flow, risk limits
RULES:
  - Never allocate >50% to one scheme
  - Kill schemes with ROI < 0 for 3+ days
  - Scale schemes with ROI > 100% + stable approval
  - Reserve 20% for testing new offers
FORMAT: Budget plan per scheme + reasoning
```

### 4. Risk Alerts
- **Approval rate drop** > 20% from baseline → investigate shaving
- **Payout delay** > network terms → pause traffic
- **Creative fatigue** → CTR drop > 30% → rotate
- **Geo ban / offer cap** → immediate pause
- **Cash flow crunch** → projected balance < 3 days spend

## Integration Points

- **finance-core** — SQLite ledger (spend, revenue, payouts). Use `get_finance_summary()` for full state, `get_pnl(30)`, `get_scheme_economics()`, `get_tax_liability()`, `get_pending_withdrawals()`.
- **arbitrage-sensors** — Offer scanner + gap calculator + medium sensor run. Key scripts:
  - `scripts/gap_calculator.py` → `run_calculation()` processes cached offers, emits `arbitrage_gap_found`
  - `scripts/medium_sensor_run.py` → hourly run: scans 8 networks (24 offers), calculates gaps, scores 0-100, sends Telegram alerts for HIGH+ (score ≥50), dispatches deep-dive via delegate_task
  - `scripts/format_short_alert.py` → formats alerts <8 lines plain text for Telegram delivery
- **cpa-income-pipeline** — Campaign metadata
- **cron-maintenance** — Daily reconciliation job

## Actual Implementation Pattern (2026-07-24)

The daily P&L reconciliation is executed by combining three components:

1. **finance_core** — `get_finance_summary()` returns P&L 30d, scheme economics, tax liability, pending withdrawals, USD/RUB rate
2. **gap_calculator** — `run_calculation()` processes cached CPA offers against mock traffic costs, emits `arbitrage_gap_found` events, stores gaps in `cache/arbitrage_gaps.json`
3. **medium_sensor_run** — Loads all offers (including 4 new target networks: AdCombo, CPAlead, MaxBounty, CPATrend), calculates gaps, scores them 0-100 (Impact×Urgency×Confidence/10), sends Telegram alerts for HIGH+ (score ≥50), dispatches deep-dive via `delegate_task` for HIGH/CRITICAL

The daily brief is generated by a script that:
- Scores each scheme 1-10 on viability (ROI stability, approval trend, payout reliability, scalability, traffic diversification)
- Tags: 🟢 SCALE (ROI>100%), 🟡 MAINTAIN (ROI>0), 🟠 FIX (ROI<0 but spend<10), 🔴 KILL (ROI<0 spend≥10)
- Recommends budget allocation per rules (max 50% per scheme, kill negative ROI, scale >100% ROI, reserve 20% for testing)
- Outputs Telegram-formatted table with alerts and top opportunities from arbitrage sensors

## Weekly Portfolio Review Pattern (2026-07-26)

The weekly review combines **real finance core ledger data** with **mock arbitrage sensor signals**:

```python
# 1. Get REAL P&L from finance core

#    REAL DATA SECTION — Finance core ledger (trustable)
#    MOCK DATA SECTION — Sensor gaps (hypotheses, validate live)
#    DECISIONS SECTION — Budget allocation, scale/kill/test

**Critical Rule:** Never conflate real ledger data with mock sensor data in output. Every mock signal must be labeled "MOCK — validate live before deploy".

## Dispatch Pattern (for multi-scheme analysis)

```python
# Parallel analysis of all active schemes
tasks = [
    {"goal": f"Analyze scheme {s['name']}: 14-day P&L, ROI stability, approval trend, scalability ceiling", 
     "context": {"scheme": s, "ledger": ledger_data}, 
     "role": "leaf"}
    for s in active_schemes
]
results = delegate_task(tasks=tasks, timeout=300)

# Timeout = 5 min. If a scheme has massive data, worker may hang.
# On timeout: redispatch with "focus only on last 7 days + summary metrics"
```

## Timeout Handling

```python
# If worker times out on scheme analysis:
# 1. Redispatch with simplified brief:
#    "Analyze {scheme}: 7-day P&L, daily ROI, approval rate trend, 1-sentence action"
# 2. If redispatch times out → ESCALATE: "Data volume too high for worker, need direct DB query"
# 3. Log timeout pattern → self-improving-skills detects "large ledger = timeout" pattern
```
