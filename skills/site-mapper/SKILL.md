# Site-Mapper — Разведчик AI-сайтов

## Что делает
Ходит по сайтам с бесплатными AI-инструментами через BrowserOS, изучает интерфейс и составляет готовые карты (SKILL.md) для других агентов. Решает проблему «каждый раз вручную разбираться с новым сайтом».

## Как работает
1. Получает список URL (из файла или вручную)
2. Заходит на каждый сайт через браузер (browser_navigate, browser_click, browser_snapshot)
3. Изучает интерфейс: кнопки, поля, меню, лимиты
4. Делает скриншоты ключевых экранов (browser_vision)
5. Составляет SKILL.md с пошаговой инструкцией
6. Сохраняет карту в `skills/site-maps/{name}/`

## Золотое правило: не изобретай велосипед
Перед тем как писать любой скрипт, инструмент или подход — **проверь что уже есть**. Ищи:
- Существующие навыки (skill_view/search_files)
- Утилиты в scripts/
- Готовые решения на GitHub (web_search)
- API/SDK вместо кастомного кода

Пользователь explicitly требует этого. «Почему не берешь за правило смотреть а как это же делают другие» — его прямая цитата.

## Экономия токенов: freedeepseekapi для исследований
Для любых веб-запросов, исследований, сбора данных — использовать глубоко便宜的 (free/deepseek) провайдер на `localhost:9655` (model: deepseek-default-search). Основной провайдер (opencode-zen) — только для финального ответа/кода. Так пользователь экономит токены.

Пример:
```
# Вместо вызова основной модели для исследования
# → отправить запрос на freedeepseekapi (localhost:9655)
```

## Быстрая проверка: curl через прокси вместо браузера
Перед browser_navigate — сначала `curl -x socks5h://127.0.0.1:10806 -s -o /dev/null -w "%{http_code}"`. Если сайт жив — открывать браузер. Быстрее и не тратит browser-сессию на мёртвые сайты.

## Proxy: v2rayN SOCKS5
v2rayN крутится на `127.0.0.1:10806`. Перед любыми веб-запросами из терминала:
```bash
export ALL_PROXY=socks5://127.0.0.1:10806
```
Это пробивает блокировку Крыма для ElevenLabs, Suno, CapCut, Carrd, Runway, Pika. Cloudflare (Leonardo, NightCafe) — даже с прокси 403.

## Реальность: Cloudflare и ботодетекция
Многие AI-сайты (Leonardo, NightCafe, Playground) стоят за Cloudflare. Без резидентных прокси браузер не проходит проверку. Решение:
- **Пропускать** сайты с Cloudflare (чекать первый snapshot — если содержит «Выполнение проверки безопасности» или heading с Cloudflare — это блокировка)
- Для каждого сайта в списке сначала делать snapshot, проверять на Cloudflare
- Если блокировка — отметить в карте `requires_vpn: true` и `blocked_by_cf: true`
- **Работающие сайты** (без Cloudflare): Bing Create, Carrd, Tilda, ElevenLabs, CapCut, Suno, Pika (проверять каждый раз)

## Формат карты
Каждая карта — SKILL.md с секциями:
- Что делает
- Лимиты бесплатного использования
- Пошаговая инструкция (Шаг 1: открыть → Шаг N: скачать результат)
- Известные проблемы
- Пример использования

Старая версия (site_mapper.py с --save) признана нерабочей. Новый формат карт создаётся **вручную** через browser_navigate + browser_snapshot + browser_click, данные собираются в ответе ассистента, сохраняются через write_file.

## Анализ схем: смотреть с 4+ точек зрения
При изучении любого сайта/схемы/сервиса — не останавливаться на поверхностном выводе. Анализировать минимум с 4 перспектив:

1. **Поверхность** — что очевидно, что лежит на виду (бесплатный контент, реклама)
2. **Реальная монетизация** — что на самом деле продаётся (не профессии, а надежда; не обучение, а иллюзия быстрого результата)
3. **Применительно к задаче** — как это можно использовать в текущем проекте
4. **Что можно сделать иначе** — как улучшить/адаптировать схему

Пример из практики: видео «11 лёгких удалённых профессий» — поверхностно это контент для монетизации YouTube. Реально продаётся надежда на быстрый заработок. Применительно к Telegram-каналам — канал может быть не товаром, а лид-магнитом для услуги. Вместо продажи канала за $80-200 — продажа доступа к аудитории.
