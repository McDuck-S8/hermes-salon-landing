# ADR-001: Внедрение Architecture Decision Records как практики планирования

**Status:** Accepted
**Дата:** 2026-07-21
**Источник:** Прокачка навыка планирования по 5 репозиториям GitHub

---

## Context

Агент Hermes умеет действовать: писать код, запускать процессы, генерировать отчёты. Но он не умеет планировать на архитектурном уровне. Каждое решение принимается ситуативно, без документирования контекста и последствий. Это приводит к:

1. Повторению одних и тех же ошибок (нет памяти "почему выбрали X")
2. Хаотичной архитектуре: скрипты растут без связанной структуры
3. Невозможности для будущих агентов понять, почему система устроена так, а не иначе

Были рассмотрены подходы к планированию:
- OKR/SMART (постановка целей) — репозиторий недоступен (404)
- How-To-Ask-Questions (декомпозиция задач) — полезно, но это навык коммуникации, а не архитектуры
- DevOps exercises (инфраструктурное мышление) — слишком broad
- System Design Primer (проектирование систем) — полезно, но требует архитектурных знаний, которых пока нет
- **ADR (Architecture Decision Records)** — документирование решений

## Decision

Внедрить практику **Architecture Decision Records (ADR)** как основной метод планирования.

Каждое архитектурное решение теперь документируется в формате:
```
# ADR-N: Заголовок
Status: [proposed | accepted | deprecated | superseded]
Context: проблема, ограничения, рассмотренные альтернативы
Decision: что выбрано и почему
Consequences: трейдоффы, последствия, что это ломает
```

ADR хранятся в `skills/planning/adr/ADR-N.md`.

## Consequences

**Плюсы:**
- Каждое решение имеет "бумажный след" — можно вернуться и понять контекст
- Уменьшает количество повторных ошибок
- Создаёт институциональную память для будущих агентов
- ADR можно ревьювить и улучшать

**Минусы:**
- Требует дисциплины: писать ADR перед или сразу после каждого архитектурного решения
- Замедляет принятие решений на 1-2 минуты (но это окупается)

**Что меняется прямо сейчас:**
1. Создаётся `skills/planning/` с ADR-логом
2. Каждое ключевое решение в session — с кратким ADR в ответе
3. ADR-лог пополняется по мере работы
