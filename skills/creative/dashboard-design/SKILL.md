# Dashboard Design — Live Data HTML Dashboards

Use this skill when the user needs a **working dashboard** that shows real-time or periodically refreshed data from their system (kanban tasks, cron jobs, profiles, logs, metrics). Not a static mockup — a functional single-file HTML artifact they can open in a browser.

## When to Use This Skill

- "Show me my kanban board in a browser"
- "Build a dashboard for my cron jobs"
- "Visualize my agent fleet status"
- "Monitor Hermes system health"
- Any request for a **live view** of structured data that updates

## When NOT to Use

- Static landing pages, prototypes, decks → use `claude-design`
- Known-brand lookalikes (Stripe, Linear, Vercel) → use `popular-web-designs`
- Design token specs → use `design-md`

## Workflow Priority: Improve Before Build

When the user points to an existing report or dashboard (HTML, auto-generated, static):

1. **Check if it already exists** — use `search_files` or `ls` to verify the path. Do not assume it's missing.
2. **Read the file** before editing to understand its structure, font stack, color scheme, and data source.
3. **Extend in place** — add JS interactivity, light mode, refresh capability via targeted patches. Do not rewrite the entire file unless asked.
4. **Note auto-generation** — if the file is generated by a script (Ripple Engine, cron, etc.), inline edits will be overwritten on the next run. Mention this to the user and offer to patch the generator script for permanent changes.

## Improving Auto-Generated Reports

When enhancing a report produced by another system (scheduler, Ripple Engine, cron):

- **Assess what's feasible in-place:** light mode CSS, keyboard shortcuts, theme persistence via localStorage — these survive regeneration if the generator doesn't touch the style/script blocks you added (common for templates that inject only body content).
- **If the generator has no live-data JSON output:** add a pseudo-live layer (localStorage for user preferences, keybind for manual refresh) instead of forcing a JSON pipeline.
- **Prefer CDN-free improvements** — system fonts, no external deps. The report may be opened offline.
- **Document the gap:** tell the user what was improved in-place vs. what requires generator changes.

## Core Principles

1. **Self-contained HTML** — one file, zero build step, opens via `file://` or local HTTP
2. **Live data via fetch** — JSON files served alongside, or inline data + `setInterval` refresh
3. **Auto dark/light** — `@media (prefers-color-scheme: dark)` mandatory
4. **No console errors** — verify in browser before delivering
5. **Keyboard accessible** — ESC closes modals, Tab navigates, Enter activates

## Data Fetching Pattern

```javascript
const DATA_FILES = {
  tasks: 'tasks.json',
  crons: 'crons.json',
  profiles: 'profiles.json',
  health: 'health.json'
};

async function loadAll() {
  const results = await Promise.allSettled(
    Object.entries(DATA_FILES).map(([k, url]) => fetch(url).then(r => r.json()))
  );
  return Object.fromEntries(
    Object.keys(DATA_FILES).map((k, i) => [k, results[i].status === 'fulfilled' ? results[i].value : []])
  );
}
```

## Auto-Refresh

```javascript
const REFRESH_MS = 30000;
let refreshTimer = setInterval(loadAndRender, REFRESH_MS);
function refreshNow() { loadAndRender(); clearInterval(refreshTimer); refreshTimer = setInterval(loadAndRender, REFRESH_MS); }
```

## Modal Detail View (Reusable)

```javascript
function openModal(title, html) {
  document.getElementById('modal-title').textContent = title;
  document.getElementById('modal-body').innerHTML = html;
  document.getElementById('modal').classList.add('open');
}
function closeModal() { document.getElementById('modal').classList.remove('open'); }
document.addEventListener('keydown', e => e.key === 'Escape' && closeModal());
```

## Kanban Column Rendering

```javascript
const COLUMNS = [
  { id: 'ready', label: 'Ready', color: 'info' },
  { id: 'running', label: 'Running', color: 'ok' },
  { id: 'blocked', label: 'Blocked', color: 'err' },
  { id: 'done', label: 'Done', color: 'muted' }
];

function renderKanban(tasks) {
  const byStatus = Object.groupBy(tasks, t => t.status);
  return COLUMNS.map(col => `
    <div class="kanban-col ${col.id}" data-status="${col.id}">
      <h3>${col.label} <span class="count">${(byStatus[col.id] || []).length}</span></h3>
      <div class="task-list">${(byStatus[col.id] || []).map(renderTaskCard).join('')}</div>
    </div>
  `).join('');
}
```

<div class="cron-item ${cron.last_status === 'error' ? 'error' : cron.last_status === 'ok' ? 'ok' : ''}">

## File Output Convention

- Dashboard HTML → `dashboard_data/dashboard.html`
- JSON data files → `dashboard_data/{tasks,crons,profiles,health}.json`
- Generator script → `scripts/gen_dashboard.py` (runs `hermes` CLI, writes JSON)
- Server script → `scripts/serve_dashboard.py` (SimpleHTTPRequestHandler on :8765)

## Verification Checklist

Before delivering, open the HTML in browser and verify:
- [ ] No console errors (network, JS, CSS)
- [ ] Data loads and renders
- [ ] Dark mode works (toggle OS theme or DevTools)
- [ ] Light mode works
- [ ] Refresh button works
- [ ] Modal opens/closes (click card → modal, ESC → close)
- [ ] Responsive: stacks on mobile, grid on desktop
- [ ] Footer shows "Data updated: <timestamp> | <path to JSON files>"
- [ ] Copy-to-clipboard button for JSON directory path

## Pitfalls

- Don't design a static mockup when the user needs a working dashboard — build the fetcher + renderer
- Don't hardcode colors; use CSS variables with `prefers-color-scheme`
- Don't assume an existing report doesn't exist — check the filesystem first with `search_files` or `ls`. False negatives waste time and annoy the user.
- Don't rewrite an auto-generated file from scratch unless the user explicitly asks for a replacement — extend in place first.
- Don't forget CORS — serve JSON from same origin (SimpleHTTPRequestHandler does this)
- Don't leave `console.log` spam in production dashboard code
- Don't assume the user knows how to run a Python HTTP server — include the server script
- Don't skip the modal detail view — kanban cards need drill-down
- Don't use external CDN fonts — system fonts only, works offline
