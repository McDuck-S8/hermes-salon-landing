# Crystal — Персональный Development Advisor

## Purpose
Crystal — система самосознания и развития, которая:
1. Наблюдает **пользователя** (сессии, запросы, поправки)
2. Понимает его **потребности** и паттерны
3. Учитывает **энергию** и **зависимости**
4. Определяет **приоритеты** и **риск**
5. Управляет **отделами** (домены инструментов)
6. Находит **отставание** и делает агрейд
7. **Эволюционирует сам** (становится лучше)

**Реализация:** `scripts/crystal/` (22 модуля, 550+ строк)
7. **Эволюционирует сам** (становится лучше)
8. **Сам пушит** важное без запроса
9. Следит за **внешним миром** (новые инструменты, API, тренды)
10. Отслеживает **долгосрочные цели** пользователя
10. Тестирует изменения **перед применением**
11. **Откатывает** если сломало
12. Ведёт **историю** всех изменений
13. Находит **синергию** между отделами
14. Использует **базу знаний** (не изобретать заново)
15. Адаптирует **стиль общения** под пользователя
16. Следит за **бюджетом и лимитами**
17. **Эволюционирует сам** (становится лучше)
18. Направляет **развитие** системы

## Ownership
Crystal — не diagnostic tool. Не KC-observer. Это **персональный development advisor**.
Источник: `scripts/crystal.py` + `scripts/crystal/` (модули)

## Архитектура — 22 Модуля

### Модуль 1: Session Reader
Читает сессии, извлекает сырые сигналы.

Данные на вход:
- Запросы пользователя (что просит)
- Поправки (что исправляет)
- Фразы фрустрации ("ты каждый раз", "когда же")
- Рабочие паттерны (какие инструменты, скиллы)
- Не сделанное (чего хотел но не получил)

Выход: `list[Signal]` → `cache/crystal/signals.json`

---

### Модуль 2: Pattern Detector
Находит повторяющиеся паттерны из сигналов.

Типы паттернов:
- `correction_loop` — одну ошибку поправляют >2 раз
- `missing_knowledge` — вопрос который агент не может ответить
- `frustration_spike` — серия негативных фраз подряд
- `workflow_success` — рабочий паттерн который стоит повторять
- `unmet_need` — запрос без удовлетворённого результата

Выход: `list[Pattern]` с frequency и severity → `cache/crystal/patterns.json`

---

### Модуль 3: Need Analyzer
Из паттернов формирует конкретные потребности.

Трансформация:
- `correction_loop` → "скилл X нужно исправить"
- `missing_knowledge` → "нужен новый скилл/документация"
- `frustration_spike` → "архитектурная проблема в Y"
- `workflow_success` → "закрепить как скилл"
- `unmet_need` → "нужен инструмент Z"

Выход: `list[Need]` с priority и impact → `cache/crystal/needs.json`

---

### Модуль 4: Priority Engine
Определяет что делать ПЕРВЫМ. У пользователяlimited time.

Факторы:
- Urgency — как быстро нужно (deprecated API vs "хотелось бы")
- Impact — сколько пользователей/систем это затронет
- Effort — сколько времени/усилий
- Dependencies — что блокирует другие задачи

Выход: `list[Proposal]` отсортированный по priority → `cache/crystal/priority.json`

---

### Модуль 5: User Energy Model
Считывает состояние пользователя чтобы адаптировать предложения.

Сигналы:
- Фразы фрустрации → "пользователь устал, предложить мелочи"
- Длинные сессии → "пользователь в ресурсе, можно сложное"
- Быстрые запросы → "пользователь торопится, только срочное"
- Молчание → "пользователь занят, не беспокоить"

Выход: `EnergyState` (low/medium/high) → влияет на Priority Engine

---

### Модуль 6: Dependency Map
Понимает что от чего зависит.

Типы зависимостей:
- Blocker — "нельзя X без Y" (Telegram бот без хостинга)
- Enabler — "X ускоряет Y" (новый скилл → быстрее задачи)
- Coupled — "X и Y вместе" (монетизация + контент)

Выход: `DependencyGraph` → `cache/crystal/dependencies.json`

---

### Модуль 7: Risk Assessment
Оценивает безопасность каждого действия.

Уровни:
- `safe` — patch SKILL.md, обновление memory, minor DOX update
- `moderate` — новый скилл, обновление зависимостей
- `risky` — архитектурные изменения, смена провайдера
- `critical` — миграция данных, изменение security

Выход: `RiskLevel` для каждого Proposal → влияет на Development Proposer

---

### Модуль 8: Development Proposer
Из потребностей + приоритетов + риска генерирует конкретные действия.

Действия:
- `create_skill` — создать новый скилл
- `patch_skill` — исправить существующий
- `update_dox` — обновить AGENTS.md
- `update_memory` — обновить memory
- `new_tool` — предложить новый инструмент
- `architecture_change` — изменить архитектуру

Выход: `list[Proposal]` с risk_level + priority → `cache/crystal/proposals.json`

---

### Модуль 9: Staleness Detector

Что проверяет:
- Версии скиллов (установлен vs доступный в hub)
- Зависимости (пакеты в requirements/pyproject)
- Конфигурация (config.yaml — deprecated поля, новые опции)
- Документация (AGENTS.md — устаревшие контракты)
- Инструменты (есть ли более новые/лучшие альтернативы)
- Провайдеры (модели, API — что обновилось, что умерло)

Что делает:
- Автоматически: обновление скиллов, patch SKILL.md, обновление memory
- С предложением: архитектурные изменения, новые инструменты, смена провайдера
- С отчётом: что нашёл, что сделал, что предлагаю

---

### Модуль 10: Proactive Alerts
Сам пушит важное без запроса пользователя.

Тригеры:
- API изменился → "YouTube API v3 deprecated, обнови скилл"
- Dependencies устарели → "3 пакета требуют обновления"
- Критическая уязвимость → "CVE в зависимостях, нужно обновить"
- Пользователь долго не работал → "вот что можно сделать когда будет время"

Доставка:
- В следующей сессии (если пользователь在线)
- В crystal_tasks.json (если offline)
- В memory (если важно но не срочно)

---

### Модуль 11: Memory Integration
Читает и пишет memory пользователя.

Что читает:
- Предпочтения пользователя (что нравится, что нет)
- Историю (что уже пробовал, что работало)
- Окружение (ОС, инструменты, провайдеры)

Что пишет:
- Новые предпочтения (из паттернов)
- Исправления (пользователь поправил → запомнить)
- Решения (что выбрали и почему)

---

### Модуль 12: Feedback Loop
Отслеживает помогли ли изменения.

Метрики:
- `correction_count` до/после
- `frustration_signals` до/после
- `unmet_needs` до/после
- `workflow_success_rate`

Выход: `Assessment` → `cache/crystal/feedback.json`

---

### Модуль 13: Versioning
История изменений Crystal.

Что хранит:
- Какие изменения были сделаны
- Когда и почему
- Какой эффект дали (feedback score)
- Какие альтернативы рассматривались

Выход: `cache/crystal/changelog.json`

---

### Модуль 14: Cross-department Synergy
Находит связи между отделами.

Типы связей:
- Content Pipeline: YouTube → social-media → monetization
- Tech Stack: ai-core → devops → websites
- Data Flow: data → all departments
- Skill Reuse: один скилл решает задачи в нескольких отделах

Выход: `cache/crystal/synergies.json`

---

### Модуль 15: Long-term Goals
Отслеживает стратегические цели пользователя.

Что отслеживает:
- Куда пользователь идёт (долгосрочные планы)
- Что уже достигнуто
- Что блокирует прогресс
- Какие вехи на горизонте

Выход: `cache/crystal/goals.json`

---

### Модуль 16: External Intelligence
Мониторинг внешнего мира.

Источники:
- GitHub trending (новые инструменты)
- PyPI / npm (новые пакеты)
- AI news (новые модели, API)
- Competitor analysis (что делают другие)
- Security feeds (CVE, уязвимости)

Выход: `cache/crystal/intelligence.json`

---

### Модуль 17: Automated Testing
Тест перед применением изменений.

Что тестирует:
- SKILL.md — синтаксис, ссылки, контракты
- Python код — import, syntax, basic run
- DOX — перекossылки, устаревшие ссылки
- Config — валидация полей

Уровни:
- `quick` — syntax check (секунды)
- `standard` — import + basic run (минуты)
- `full` — полный тест (если критично)

---

### Модуль 18: Rollback
Откат если изменение сломало.

Механизм:
- Каждое изменение версионируется
- Перед применением — snapshot
- Если feedback негативный — автоматический откат
- Ручной откат: `crystal rollback <version>`

Выход: `cache/crystal/snapshots/`

---

### Модуль 19: Knowledge Base
База проверенных решений. Не изобретать заново, а использовать то что работает.

Что хранит:
- Решённые проблемы (паттерн → решение → эффект)
- Рабочие подходы (workflow → результат)
- Провалы (что не сработало и почему)
- Советы пользователя (что он рекомендовал)

Использование:
- При proposal — проверить: "это уже решалось?"
- При выборе подхода — использовать проверенный
- При ошибке — "так уже было, вот как исправили"

Выход: `cache/crystal/knowledge_base.json`

---

### Модуль 20: Communication Adapter
Адаптирует стиль общения под пользователя.

Что учитывает:
- Язык (русский/английский)
- Длина (кратко/подробно)
- Техничность (простой/технический)
- Тон (деловой/дружеский)
- Формат (текст/таблицы/списки)

Как учит:
- Пользователь поправил тон → запомнить
- Пользователь сказал "короче" → запомнить
- Длинные ответы игнорируются → укорачивать

Выход: `cache/crystal/communication.json`

---

### Модуль 21: Resource Monitor
Следит за бюджетом и лимитами.

Что отслеживает:
- API-лимиты (requests/day, tokens/month)
- Бюджет (сколько потрачено, сколько осталось)
- Время (сколько занимает каждый модуль)
- Память (сколько места занимают данные)

Что делает:
- Если бюджет на исходе → "используй более дешёвую модель"
- Если лимит API → "подожди, лимит исчерпан"
- Если время > порога → "оптимизируй этот модуль"
- Если память > порога → "почисти старые данные"

Выход: `cache/crystal/resources.json`

---

### Модуль 22: Self-Evolution
Crystal эволюционирует сам. Не только "пользователь поправил → запомнить", но и "я сам нашёл что мой модуль работает плохо → переписать".

Что отслеживает:
- Какие модули работают плохо (низкий feedback score)
- Какие модули узкое место (время, память)
- Какие подходы устарели (Knowledge Base)
- Какие паттерны не покрыты (новые типы задач)

Что делает:
- Автоматически: оптимизация модулей, обновление Knowledge Base
- С предложением: новые модули, изменение архитектуры
- С отчётом: "я стал лучше на X% за последний месяц"

Выход: `cache/crystal/evolution.json`

## Правила

1. **Crystal наблюдает и предлагает.** Не делает опасных изменений без подтверждения.
2. **Автоматически:** patch скиллов, обновление memory, minor DOX updates.
3. **С подтверждением:** новые скиллы, архитектурные изменения, смена провайдеров.
4. **Каждый отдел** имеет свой AGENTS.md с контрактами.
5. **Feedback** — обязательно. Каждое изменение оценивается.
6. **Тест перед применением.** Никаких изменений без проверки.
7. **Откат** — автоматический если feedback негативный.
8. **Версионирование** — каждое изменение записывается в changelog.
9. **Синергия** — ищи связи между отделами, используй кросс-отделные возможности.
10. **Внешний мир** — мониторь новые инструменты и тренды.
11. **База знаний** — используй проверенные решения, не изобретай заново.
12. **Стиль общения** — адаптируй под пользователя, запоминай поправки.
13. **Бюджет** — следи за лимитами, предлагай дешёвые альтернативы.
14. **Самоэволюция** — ищи как стать лучше, оптимизируй модули.

## Связь с DOX

Crystal обновляет DOX:
- Новый скилл → AGENTS.md в skills/
- Архитектурное изменение → AGENTS.md в对应目录
- Новый отдел → AGENTS.md для отдела
- Memory → user profile + memory

DOX — карта системы. Crystal — навигатор.
