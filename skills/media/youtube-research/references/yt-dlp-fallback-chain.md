# yt-dlp Fallback Chain Reference

When browser-based YouTube extraction fails (timeout, 403, cookie wall), use this fallback chain:

## Chain (fastest first)

| Method | Speed | Reliability | Use Case |
|--------|-------|-------------|----------|
| oembed API + SOCKS5 | ~200ms | High | Quick metadata (title, author, thumbnail) |
| yt-dlp (local venv) | ~5-15s | Medium | Full metadata + subtitles + description |
| Invidious API | ~2-5s | Low | Backup metadata when direct blocked |
| yewtu.be / Invidious instances | ~3-10s | Low | Public instance extraction |
| curl + v2rayN + HTML regex | ~2-5s | Low | Direct HTML scraping through proxy |
| BrowserClaw / ghost-surfer | ~30-60s | High | Last resort: full browser with auth |

## yt-dlp via module (Python 3.13 compat)

```bash
# CRITICAL: Use the venv python explicitly, NOT system python
/d/Portable_Soft/hermes/hermes-agent/.venv/Scripts/python.exe -m yt_dlp \
  --dump-json --no-download \
  --proxy socks5://127.0.0.1:10806 \
  "https://www.youtube.com/watch?v=VIDEO_ID"
```

**Pitfall**: Running `python -m yt_dlp` from system python fails with "No module named yt_dlp" even if installed in venv. Always use full venv path.

**Pitfall 2**: `--proxy socks5://127.0.0.1:10806` causes 429/timeout on YouTube. Works for oembed but NOT for yt-dlp full extraction.

## YouTube Anti-Bot Reality (2026-07-29)

| Layer | What YouTube Checks | Bot Fails Because |
|-------|---------------------|-------------------|
| 1. IP Reputation | Datacenter/proxy IP lists | v2rayN exit nodes often flagged |
| 2. TLS Fingerprint | JA3/JA4 client hello | Python requests ≠ Chrome |
| 3. HTTP Headers | Missing/incorrect headers | No Sec-CH-UA, wrong order |
| 4. PO Token | Required for video streams | Only generated by real browser JS |
| 5. Visitor Data | Tracks session across requests | Rotates, tied to cookies |
| 6. Cookie Validation | Rotated frequently | Browser cookies invalidate in hours |

**What works for METADATA only**: oembed through SOCKS5 (bypasses most checks)
**What works for FULL extraction**: Authenticated browser session (CDP 9222) with real cookies

## Working Fallback for DESIGN_LEARNER

Since full yt-dlp extraction is blocked, the pipeline uses:

1. **oembed via SOCKS5** → title, channel, thumbnail (WORKS)
2. **Cache result** → tactical_buffer with video_id, title, channel
3. **Manual/periodic deep extraction** → Run yt-dlp with browser cookies when needed
4. **Subtitles** → Download via yt-dlp separately (sometimes works without PO Token)

## Practical Code Pattern (from youtube_pipeline.py)

```python
def get_metadata_oembed(self, video_id: str) -> Optional[Dict]:
    """Fast metadata via oembed API through SOCKS5 proxy (~200ms)."""
    try:
        result = subprocess.run([
            "curl", "-sL", "--max-time", "10",
            "--proxy", "socks5://127.0.0.1:10806",
            f"https://www.youtube.com/oembed?url=https://www.youtube.com/watch?v={video_id}&format=json"
        ], capture_output=True, text=True, timeout=15)
        if result.returncode == 0 and result.stdout:
            data = json.loads(result.stdout)
            return {
                "title": data.get("title"),
                "author": data.get("author_name"),
                "author_url": data.get("author_url"),
                "video_id": video_id,
                "source": "oembed"
            }
    except Exception:
        pass
    return None

def process_video(self, url: str, lang: str = "en,ru") -> Dict:
    """Fallback chain: oembed → HTML proxy → yt-dlp → subtitles"""
    # Step 1: oembed (fastest, works)
    meta = self.get_metadata_oembed(video_id)
    if meta:
        result.update(meta)
    
    # Step 2: HTML + proxy (description + channel) - often fails
    html = self.get_html_metadata(video_id)
    
    # Step 3: Full yt-dlp (blocked by 429/PO Token)
    full = self.get_full_metadata(video_id)
    
    # Step 4: Subtitles (sometimes works)
    self.download_subtitles(video_id, lang)
    
    return result
```
