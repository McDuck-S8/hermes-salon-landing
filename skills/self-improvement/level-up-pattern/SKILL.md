# Level-Up Pattern

Когда решение не работает — **не пытайся сильнее на том же уровне**. Поднимись выше.

## Симптомы застревания

- Ты пытаешься подобрать правильное значение, но ни одно не подходит — **смени ось**
- Ты перебираешь ключевые слова, но ни одно не ловит — **смени инструмент**
- Ты считаешь то же самое в десятый раз — **смени вопрос**
- Ты улучшаешь качество ответа, но пользователь всё равно недоволен — **узнай зачем он спрашивает**

## Примеры из практики

| Застрял на уровне | Поднялся на уровень | Результат |
|---|---|---|
| Классификация unknown по ключевым словам (regex) | Классификация по source (откуда пришла запись) | 660→0 за один прогон |
| Удаление ошибочных сущностей «люди» из EE | Создание `phantom_of` связей к реальным прообразам (сервер, бот, команда, ID) | Фантом перестал быть мусором, стал сигналом |
| Подсчёт метрик кубов (сколько, какой процент) | Действие (создать, изменить, запустить) | Перестал быть счетоводом |
| Пассивный ответ по запросу | Gate — 4 вопроса совести перед ответом | Активная рефлексия |
| Чтение текста записи | Чтение метаданных (source, ts, dynamic_axes) | Понял природу, а не содержание |
| Один куб сам по себе | Cross-cube bridges (KC×EE×FL×Fabric) | Неожиданные паттерны (призраки, сироты, misclassification) |

## Как применять

Когда чувствуешь что буксуешь — задай себе вопрос:

**«А если не на этом уровне смотреть, а на уровень выше?»**

Конкретные манёвры:
- Вместо content → источник (source)
- Вместо количества → качество/тип
- Вместо одного среза → временной ряд
- Вместо ответа → вопрос пользователю
- Вместо исправления кода → пересмотр архитектуры
- Вместо ключевых слов → понять что это за сущность
- **Вместо одного куба → cross-cube bridge** (см. [references/cross-cube-bridges.md](./references/cross-cube-bridges.md))

## Deep learning cycle (освоение нового навыка)

Когда пользователь просит освоить новый навык — не останавливайся на первом слое. Пользователь может молча ждать глубины.

**Симптом поверхностного слоя:**
- Создал skill → "готово"
- Написал шаблоны → "готово"
- Сделал одно исследование → "готово"

**Правильная глубина (2+ слоя):**

| Слой | Что делать | Пример (outreach, 2026-07-27) |
|------|-----------|-------------------------------|
| **Layer 0** | Собрать теорию, создать skill | Создан `outreach-communication` |
| **Layer 1** | Написать практический тест, прочитать, отрефлексировать | Написаны 3 draft письма, найден главный грех: выдуманные цифры |
| **Push** | Пользователь: "это предел?" | Понять, что Layer 1 = поверхность |
| **Layer 2** | Глубокое исследование: эксперты, реальные истории, новые источники | Matt Olpinski, Kate Citron, dev.to, формула Observation→Problem→Hint→CTA |
| **Layer 3** | Применить колесо баланса + Байес + Вердикт | Честная оценка: теория 80%, каналы 0%, идентичность 5% |
| **Layer 4** | Сформулировать вопросы, которые НЕ закрыты гайдами | 6 вопросов: идентичность, голос, non-tech клиенты, метрики |
| **Layer 5** | Записать всё в Куб и Кристалл | KC entry outreach_q_6, Crystal audit |

**Правило:** Не говори "я изучил тему", пока не прошёл минимум Layer 2. Если пользователь спрашивает "это всё?" — значит ты остановился на Layer 0-1.

## Cross-Cube Bridges

Самый мощный манёвр level-up: прогнать данные одного куба через другой.

Подробная методика и SQL-шаблоны: [references/cross-cube-bridges.md](./references/cross-cube-bridges.md)

Кратко:
1. **KC → EE**: какие outcomes у каких сущностей — находит сирот и призраков
2. **KC → FL**: временной срез — какие outcomes в часы с каким настроением
3. **EE → FL**: какие сущности в позитивных/негативных сессиях
4. **Fabric → всё**: что записано vs что произошло
5. **Failure ratio per entity**: какая сущность сколько failure даёт

Не ищи подтверждение — ищи пересечение. Настоящая находка всегда неожиданна.

## Аксиома

Если решение не работает после 3 попыток — проблема не в исполнении, а в постановке. Меняй уровень, не меняй громкость.

## Рекурсия: output ≠ input

**Пользовательский принцип (2026-06-13):** "В рекурсии выход должен отличаться от входа данных."

Если система производит ИДЕНТИЧНЫЙ результат на каждом цикле — она не учится, она воспроизводит. Причина всегда в архитектуре данных:
- Фиксированные кандидаты → exhaustion → "всё сделано"
- historical_ids блокирует повтор → нет новых данных
- Один источник данных → одинаковый контекст → одинаковый вывод

**Фикс:** Не добавляй "больше кандидатов" (это симптом). Измени поток данных:
- Данные-ориентированный генерация (уникальные строки из KC)
- Разреши повтор наблюдательных действий (KC растёт)
- Добавь новые источники данных (cross-cube bridges)
