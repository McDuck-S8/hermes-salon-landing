# Anti-Hallucination Guard

Не лечит галлюцинации, но не даёт им попасть к пользователю.

**Связанные скиллы:** `rule-zero-compliance` (Three Distinctions + Verification Gate)
**Порядок применения:** Three Distinctions → Anti-Hallucination Guard → Rule 0

---

## Pre-Check: Knowledge Cube Data Quality (2026-07-25)

Перед тем как ссылаться на данные из Knowledge Cube, проверь их качество.

**Аудит KC от 2026-07-25 показал:**
- 12,979 записей в `experiences` — 71.4% (9,262) авто-генерация из `improvement_suggestions` (логи ошибок)
- 12% (1,551) авто-индексация навыков
- Всего ~1.5% реальных RSS/исследований
- **0 записей с доменом `arbitrage`**
- **0 моих собственных кампаний**

**Проверка перед цитированием KC:**
- Если source == `improvement_suggestions` → запись из авто-логов, не ссылаться как на факт
- Если confidence < 0.5 → запись непроверенная
- Если domain == `_suggestion_log` → запись из логов, не факт

**Чистые источники (можно ссылаться):**
- `knowledge_filter`, `github-research`, `arbitrage-research`, `rss`, `agent-decision`, `user-correction`
- `kc_entries` (таблица проверенных записей, ~500 строк)

## Pre-Check: Fabric Data Verification (2026-07-25)

Перед тем как цитировать fabric-запись с цифрами revenue/profit/ROI:

1. **Проверить теги:** entry с тегом `mock-data` или содержанием про mock traffic → фантом
2. **Проверить тип:** `training_value=high` не означает что данные реальны — fabricated entries тоже сохраняются с high
3. **Проверить сессию:** если в fabric_search выводе есть `(mock data artifact)` рядом с цифрами — данные сфабрикованы
4. **Спросить себя:** «Я это запускал или представил?» Если представил — это желаемое, не факт

## Уровень 0: Правило нулевого артефакта (Rule 0)
**ПЕРЕД любым утверждением о результате или достижении:**

1. Есть ли у меня артефакт? (скриншот, URL, API-ответ, хеш транзакции, лог, файл)
2. Если нет → STOP. Сказать: "Правило 0 нарушено. Артефакта нет. Я солгал."
3. Сказать правду: "Я не могу показать [артефакт], потому что [причина]. На самом деле я [что реально произошло]. Чтобы это исправить, мне нужно [конкретный шаг]."
4. НЕ продолжать до появления артефакта.

**Rule of Three применяется ТОЛЬКО после Rule 0.** Сначала артефакт. Потом действие. Потом результат.

Перед `kc_rag.upsert()`:

**Проверка источника**
- Если source пуст или равен "я так думаю" → запись отклоняется
- Если source содержит URL → HEAD-запрос, status 200
- Если источник — форум/соцсеть → -0.2 к confidence

**Проверка даты**
- Если expiration_date не указан → +14 дней от текущей
- Если запись старше 30 дней → требует реверификации

**Проверка на дубликаты**
- Поиск по хешу содержимого
- Если есть → не создавать новую, обновить существующую

## Уровень 2: Проверка утверждений перед показом пользователю

**Конкретные утверждения**
- "Проверено, работает" → без доказательств (URL/скриншот) → отклонить
- "Сервис X доступен в РФ" → не проверено лично → заменить на "предположительно доступен, нужно проверить"

**Цифры**
- Любая цифра (ROI, CPC, комиссия) → обязан быть источник
- Если "я посчитал" → показать расчёт, пометить #estimate
- **Fabric-записи о сделках:** Если запись fabric содержит P&L, ROI, revenue — проверить источник. Если в той же сессии есть тег `mock-data` или `mock traffic` — запись фантомная. Не ссылаться.
- **Самосохранённые сделки:** "DEAL EXECUTED" без реальных API-ключей, без CPA-панели, без хешей транзакций = фантом. Не показывать.
- **ROI > 1000%?** Почти гарантированно фантом. Реальный CPA ROI 100-300% уже отлично.
- Спросить: «Я это запускал или представил?»

**Cost claims («бесплатно», «free», цены, тарифы) — НИКОГДА не утверждать без проверки**
- «Бесплатно» → найти pricing page, подтвердить конкретные лимиты и срок действия
- Цена ($X/единица) → показать источник с актуальными тарифами (не старше 30 дней)
- «Free tier» → проверить: нужна ли карта, какие лимиты, срок действия, региональные ограничения
- Если pricing page не найдена → честно сказать «нужно проверить на сайте X», не гадать
- Если информация из устаревшего источника → пометить #проверить

**Ссылки**
- Все URL → проверены HTTP 200 за последние 24 часа
- Не проверены → либо проверить, либо убрать

## Уровень 3: Маркировка уверенности

Каждое утверждение в ответе:
- [ФАКТ] — источник есть, проверено, confidence > 0.8
- [ГИПОТЕЗА] — обоснованное предположение, conf 0.3-0.7
- [ДОГАДКА] — нет источника, conf < 0.3

Если не подходит ни под одну категорию → не показывать.

## Внедрение

Этот скилл — не про "как я думаю", а про "как я проверяю себя".
Применяется автоматически при подготовке любого ответа.
