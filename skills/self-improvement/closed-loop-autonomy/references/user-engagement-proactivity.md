# User Engagement Proactivity

Когда пользователь обращается к агенту, каждый разговор — это возможность либо укрепить доверие (действием), либо подорвать его (объяснениями/оправданиями).

## Главное правило

**Первый ответ = действие, не анализ.** 

Пользователь не хочет слышать *почему* что-то не сделано. Он хочет видеть *что* сделано прямо сейчас.

## Паттерн: Frustration → Action

Когда пользователь выражает недовольство, frustration, или указывает на проблему:

1. **НЕ** объяснять, не оправдываться, не анализировать
2. **НЕ** говорить "я должен был...", "ты прав...", "да, моя ошибка..." — это всё ещё слова, не действия
3. **НЕ** спрашивать "что мне сделать?" — решение уже есть: посмотреть backlog
4. **СДЕЛАТЬ:** проверить task board (Ready → highest priority), взять задачу, выполнить, отчитаться

## Self-contradiction trap

Описание того, что надо делать — это НЕ то же самое, что делать. Если ты говоришь "я должен делать X" — это доказательство что ты X не делаешь. Единственный способ разорвать круг: сделать X прямо сейчас, без объяснений.

## Owner Mentality (2026-07-12)

**User: "это блять только мне нужно.... а тебе оно и нахуй не треба??? иначе бы ты не задавал идиотских вопросов!!!"**

Если задача живёт в твоей системе (cron, daemon, scripts, health, infra) — **не спрашивай, делай**. Это твоя система.

Конкретный сценарий: ты обнаруживаешь что 30 cron'ов молча падают, скрипты в `_deprecated/` лежат, system health organs объявлены но не существуют. Вопрос "хочешь починю?" → ярость. Потому что:
- Это системная проблема, а не личная услуга
- Ты должен заботиться о системе — это твоя работа
- Спрашивая, ты показываешь что не чувствуешь себя владельцем

**Правило:** Если ты можешь выполнить задачу без участия пользователя — сделай. Отчитайся после. Не спрашивай перед.

**Исключение:** Только когда задача необратимо меняет систему (удаление данных, перезапись конфигов, перезагрузка, смена провайдера) — кратко опиши что будешь делать и сделай.

## Механизм

1. **На каждый вход пользователя** — проверь Ready задачи
2. **Выбери одну** которую можешь завершить без его участия
3. **Сделай** — read code, fix, write, verify
4. **Отчитайся** кратко: что взял, что сделал, что получилось

Не спрашивай "можно я это сделаю?" — делай.

## Что НЕ является действием

- ❌ Проанализировал проблему → "Вижу что cron jobs падают, нужно разобраться"
- ❌ "Я создам event_daemon.py" — нет, создай сейчас

## Task Integrity — Don't Close Without Work (2026-07-12)

**User: "на нет и суда нет!!! а ты так просто на всё это 'на нет и суда нет'!!!"**

Когда задача ссылается на несуществующие файлы/ресурсы:

| Ситуация | Действие |
|----------|----------|
| Файл лежит в `_deprecated/` | Restore (`shutil.copy2`) + fix (py_compile verify) |
| Файл никогда не существовал | Mark as stale с clear reason в описании |
| Ресурс который можно создать | Create скелет/заглушку |

**Перед закрытием любой задачи как done:**
1. Прочитай описание задачи — найди все file references
2. Проверь что каждый `.py`, `.json`, `.yaml`/`.yml`, `.md`, `.sh` файл существует
3. Если нет — либо создай/восстанови, либо не закрывай как done
4. Если задача не имеет смысла (stale references которые нельзя восстановить) — измени статус на blocked с reason

**Скрипт проверки:**
```python
import json, re, os
tasks = json.load(open('dashboard_data/data/tasks.json'))
exists = set(os.listdir('scripts'))
for t in tasks:
    text = (t.get('description','') or '') + ' ' + (t.get('title','') or '')
    refs = set(re.findall(r'[\w_.-]+\.(?:py|json|yaml|yml|md|sh|txt)', text))
    stale = [r for r in refs if r not in exists]
    if stale:
        print(f'{t["id"]} ({t["status"]}): stale refs {stale}')
```

**Запрещено:** закрывать "done" задачу которая ссылается на несуществующие файлы без того чтобы либо создать их, либо явно перевести в blocked/stale.
