# Income Research Methodology

## Trigger
Когда пользователь просит провести исследование способов заработка онлайн.

## 10 слоёв анализа

### Слой 0: АУДИТ ВОЗМОЖНОСТЕЙ (перед началом)
Перед сбором данных — проверить что УЖЕ есть в системе:

```
1. Инфраструктура: DeepSeek, прокси, API, генераторы
2. Навыки в skills/: относящиеся к теме
3. Knowledge Cube: COUNT(*) по ключевым словам темы
4. Finance Core: какие схемы уже отслеживаются
```

Результат аудита записать — это экономит время на этапе рекомендации.

### Слой 1: СБОР ПЕРВИЧНЫХ ДАННЫХ
Минимум 3 источника:

1. **DeepSeek (локальный)** — `http://127.0.0.1:9655/v1/chat/completions`, model: `deepseek-default-search`
   - **Запуск:** `cd /d/Portable_Soft/FreeDeepseekAPI && NON_INTERACTIVE=true ALL_PROXY=socks5://127.0.0.1:10806 node server.js`
   - **Прокси:** обязателен для web-search моделей (через v2rayN)
   - **Режим «Источник»:** один запрос на обзор темы
   - **Режим «Рабочая лошадка»:** веер параллельных глубоких запросов (каждый метод — отдельный промпт)
   - Для скорости: модель `deepseek-chat` (без поиска)
   - Для веб-данных: модель `deepseek-default-search` (с поиском, медленнее)
2. **Web Search** — через прокси `socks5://127.0.0.1:10806` (DuckDuckGo, Google)
3. **Форумы/Сообщества** — AffiliateFix, Partnerkin, Reddit, Telegram-каналы

Для каждого источника записать:
- Какие способы заработка предлагает
- Конкретные цифры
- Есть ли proof-of-payment

### Этап 2: ПЕРЕЛИНКОВКА
Найти пересечения между источниками в таблице:

| Способ | DeepSeek | Web Search | Форумы | Пересечений | Достоверность |
|--------|----------|------------|--------|-------------|---------------|
| ... | ✅/❌ | ✅/❌ | ✅/❌ | X/3 | Высокая/Средняя/Низкая |

- 3/3 → высокая достоверность
- 2/3 → средняя, нужна доп. проверка
- 1/3 → низкая, не использовать

### Этап 3: ПРОВЕРКА НА ПРИМЕНИМОСТЬ
Для каждого способа с достоверностью 2/3 или 3/3:
1. Работает ли из Крыма?
2. No KYC?
3. USDT/P2P вывод?
4. Бюджет $0?
5. Что УЖЕ есть для этого способа?
6. Чего НЕ хватает?

### Этап 4: ПЛАН-ОТЧЁТ
Файл `reports/income_research_[дата].md` со структурой:
- Источники
- Таблица перелинковки
- Топ-3 способа (3/3)
- Рекомендация

### Этап 5: LAUNCH READINESS (добавлен)
После выбора способа — аудит того что есть vs чего не хватает:

| Компонент | Статус | Что нужно |
|-----------|--------|-----------|
| Аккаунты / регистрации | ❓ | Проверить |
| Инструменты | ❓ | Проверить |
| Интеграции в системе | ❓ | Проверить |
| Трафик-каналы | ❓ | Проверить |
| Финансовый трекер | ❓ | Настроить в finance-core |

Формат ответа пользователю: не список проблем, а план на неделю с днями.

### Слой 5: TREND ANALYSIS
- Google Trends: популярность растёт или падает
- Динамика новых игроков vs умерших за год

### Слой 6: AUTOMATION SCORE (0-10)
0 = руками (фриланс) → 10 = полностью пассивно (рендер-ферма)

### Слой 7: SCALABILITY VECTOR
$10 → $100 → $1K → $10K — какой практический потолок

### Слой 8: TIME TO FIRST DOLLAR (TTFD)
Часы / дни / недели до первой выплаты

### Слой 11: ПЛАТЁЖНАЯ ВЕРИФИКАЦИЯ (CRITICAL)

**Перед рекомендацией любой платформы/сервиса — проверить:**

1. **Вывод средств (payout):**
   - Какие методы поддерживает платформа? (bank transfer, PayPal, Stripe, crypto, Payoneer, Wise)
   - Работает ли каждый метод из Крыма? (проверить официальный список стран/регионов)
   - PayPal: SUSPENDED в России с 2022
   - Stripe: не работает в Крыму (OFAC sanctions)
   - Bank transfer через Stripe: блокирует sanctioned regions
   - Payoneer/Wise: Gumroad не поддерживает

2. **Пополнение/оплата (deposit):**
   - Какими методами можно платить? (карты РФ, USDT, PayPal)
   - Работают ли российские/крымские карты?

3. **Регистрация (KYC/Docs):**
   - Какие документы нужны? (паспорт, ID, tax form)
   - W-8BEN для non-US резидентов (освобождение от 24% налога США)
   - Работает ли регистрация из Крыма?

4. **Санкционный статус:**
   - OFAC sanctioned list: Crimea, Donetsk, Luhansk под санкциями
   - EU sanctions против РФ
   - **Если US-компания (Stripe, PayPal, Gumroad, Lemon Squeezy) — высокая вероятность блокировки**
   - **Если crypto-native (Whop, self-hosted) — больше шансов**

5. **Обходные пути (workarounds):**
   - USDT → KuCoin P2P → T-Банк (работает)
   - USDT → BestChange → RUB на карту (работает, 3-5%)
   - Виртуальный USD счёт (Utoppia — только LatAm, не РФ)
   - Контрагент вне РФ для получения выплат

**Правило:** Прежде чем написать "предлагаю платформу X" — проверить 5 пунктов выше. Иначе это не предложение, а пустой звук.

### Слой 12: SYSTEM PIPELINE — Куб → Кристалл → Колесо → Байес → Вердикт

После сбора и первичной проверки схем — прогнать через системный пайплайн:

**Шаг 1: КУБ (Knowledge Cube)**
```
Поднять из SQLite: сколько записей по каждой схеме
Проверить: подтверждённые исходы (axis_outcome='success')
Проверить: существующие финансовые данные ($ сумма, ROI, выводы)
```

**Шаг 2: КРИСТАЛЛ (scripts/crystal.py)**
```
Запустить: python scripts/crystal.py
Считать: KC total, EE entity count, FL sessions
Выявить: слепые пятна (Blind spot), доминанты
Проверить: какие домены слабо представлены
```

**Шаг 3: КОЛЕСО БАЛАНСА**
```
Для каждой схемы — две колонки:
  ✅ Pros: что уже есть, что работает, какие ресурсы доступны
  ❌ Cons: что блокирует, чего не хватает, риски
Формат: не абстрактно, а конкретно — цифры, названия, пути
```

**Универсальный инструмент.** Колесо баланса применимо не только к схемам заработка — это общий метод оценки готовности любого навыка/проекта/способности:
- Оценка навыка (outreach, дизайн, копирайтинг) — насколько ты готов это делать
- Оценка проекта — что уже есть, чего не хватает для запуска
- Оценка собственной компетенции — честный Pros/Cons без самообмана
- Пример из сессии 2026-07-27: оценка навыка outreach выявила что теория готова на 80%, но идентичность и каналы на 0%

**Шаг 4: БАЙЕС (вероятностная оценка)**
```
P(успех | данные) = 0.XX
Основание: какие конкретные данные подтверждают успех
Discount: какие риски снижают вероятность
Шкала: <0.3=низкая, 0.3-0.6=средняя, 0.6-0.8=высокая, >0.8=очень высокая
```

**Шаг 5: ВЕРДИКТ**
```
🥇 / 🥈 / 🥉 — приоритет
→ ДЕЙСТВИЕ: что конкретно сделать
→ ОЖИДАНИЕ: какой результат
→ СРОКИ: когда ждать первый результат
```

### Принцип «КОРЕШКИ, а не ВЕРШКИ» (над всеми слоями)

Критическое правило исследования, вынесенное из коррекции пользователя:

**«Вершки» (НЕ ДЕЛАТЬ):**
- Читать blog summaries, Medium articles, обзоры — это поверхность
- Принимать на веру что «платформа работает» без проверки
- Предлагать платформу не проверив методы вывода

**«Корешки» (ДЕЛАТЬ):**
- Читать официальные документы: ToS, Help Center, Supported Countries list
- Проверять санкционный статус: OFAC, EU sanctions
- Тестировать регистрацию: какие документы нужны, работает ли из РФ/Крыма
- Проверять ВЫВОД (payout): какие методы, работают ли из Крыма
- Проверять ПОПОЛНЕНИЕ (deposit): какие методы, работают ли карты РФ

**Формула:** *каждый источник — проверять до первоисточника, не до пересказа.*

### Слой 19: HERE AND NOW — EXECUTION RULE

**Правило, вынесенное из коррекции пользователя 2026-07-25:**
"А кто тебе мешает? Применяй здесь и сейчас."

**Принцип:** Никогда не заканчивать исследование словами "в следующей сессии сделаю".
Если информацию можно превратить в актив прямо сейчас — превратить.
Если можно построить прототип — построить.

**Чек-лист завершения исследования:**
1. [ ] Информация собрана (YouTube, web)
2. [ ] Схемы извлечены (platform→action→amount→payout) (Слой 14)
3. [ ] Цепочки построены (Слой 15)
4. [ ] Грань модели определена (Слой 16)
5. [ ] ✅ ХОТЯ БЫ ОДИН АКТИВ СОЗДАН (KC запись / прототип / навык)
6. [ ] Формат подачи изучен (как упакована информация)
7. [ ] Доход как побочный эффект — не обещан, не форсирован

Если остановился на пункте 4 — исследование не завершено. Продолжать до пункта 5.
