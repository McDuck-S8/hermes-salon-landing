# Fractal Knowledge Wheel — Фрактальное Колесо Знаний

## ⚠ Ключевое правило: Целостность данных (Data Integrity)

**Колесо показывает только то, что ты в него заложил. Если данные — фантазия, выводы — самообман.**

### Золотое правило
> Корми колесо честными данными или не корми вообще. Только реальные факты. Никаких иллюзий.

### Что значит «честные данные»
- **fill_percent** = % того что УЖЕ ЕСТЬ, а не «я знаю как сделать»
- **Факты** в sector.facts — только то что подтверждено (аккаунт создан, видео загружено, деньги выведены)
- **Никаких** «могу сделать», «знаю как», «потенциально есть» — это не факты, это предположения

### Аудит перед каждым запуском
1. Прочитай что лежит в knowledge_cube.db — откуда взялись цифры
2. Для каждого 🟢 сектора спроси: «ЧТО конкретно у меня есть? Назови файл, аккаунт, ссылку»
3. Если доказательств нет — ставь 🔴, даже если знаешь КАК делать
4. Пометь непроверенные сектора тегом `[UNVERIFIED]` — они не участвуют в анализе

### Критический провал: Источник данных

**Колесо по умолчанию читает из таблицы `experiences` в knowledge_cube.db.**

Эта таблица содержит ~13K записей, из которых **~71% — авто-сгенерированные логи ошибок** (improvement_suggestions). Только ~1.5% — реальные RSS-ленты (Partnerkin, AffiliateFix). **0% — арбитражных записей.**

**Фикс:** создана view `wheel_data` в knowledge_cube.db, которая собирает только проверенные источники:
- kc_entries (464 записи — курированные знания)
- RSS-ленты CPA-форумов
- Результаты исследований (research_traffic, research_creatives, research_cpa)
- agent-решения

**Перед запуском колеса:**
```sql
-- Проверить какой источник используется
SELECT COUNT(*) FROM experiences;  -- Если > 1000, скорее всего мусор
-- Использовать wheel_data вместо прямого чтения experiences
SELECT * FROM wheel_data;
```

Если wheel_data пуста или содержит < 100 записей — запускать колесо бессмысленно.

### Анти-паттерн (из реальной сессии)
Было: Трафик 🟢 85% — «TikTok, YouTube Shorts»
Реальность: 0 аккаунтов, 0 видео, 0 подписчиков
Правильно: Трафик 🔴 10% — «знаю платформы, но ничего не создано»

Разрыв между знанием и активом — главный источник шума в колесе.

## Концепция
Это не просто «собрать информацию по теме». Это **рекурсивный процесс с тремя режимами**:

1. **Режим 1 — Анализ**: Ключ → Аспекты → Пробелы → Задачи
2. **Режим 2 — Синтез**: Разрозненные находки → Новые ключи/связки
3. **Режим 3 — Круги Эйлера**: Пересечения аспектов → Золотые жилы, конфликты, критические пробелы

---

## Режим 3: Круги Эйлера + Колесо Баланса = Поиск Золотого Сечения

### Как это работает
- **Круги Эйлера** = аспекты темы. Каждый аспект (Трафик, Офферы, Платежи, Креативы) — отдельный круг.
- **Цвет круга** = заполненность (🟢 >80%, 🟡 30-80%, 🔴 <30%)
- **Размер круга** = важность аспекта для успеха темы (weight)
- **Пересечения кругов** = сильные моменты, где аспекты совпадают и усиливают друг друга

### Типы пересечений
| Тип | Описание | Действие |
|-----|----------|----------|
| 🟢 **Зелёное пересечение** | Все круги зелёные | Готовая связка, можно запускать прямо сейчас |
| 🔴 **Красное пересечение** | Все круги красные | Критические пробелы, блокируют запуск — чинить в первую очередь |
| 🟢🔴 **Конфликт (зелёно-красное)** | Один зелёный, другой красный | Ресурс есть, но не используется (трафик готов, креативов нет — трафик сливается впустую) |

### Пример: PWA-арбитраж беттинга на Индию
```
🟢 Трафик (85%)      🟢 Прокладка (80%)      🟢 Платежи (90%)      🟢 Вывод (85%)
🟡 Офферы (45%)      🟡 Юр. риски (40%)      🔴 Креативы (15%)     🔴 Масштабирование (10%)
```

**Зелёное пересечение**: Трафик ∩ Прокладка ∩ Платежи ∩ Вывод = готовая инфраструктура для масштабирования на другие офферы/гео.

**Красное пересечение**: Креативы ∩ Офферы = критические пробелы, блокирующие запуск.

**Конфликт**: Трафик (🟢) ∩ Креативы (🔴) = трафик есть, но нечем конвертить — сливается впустую.

## Использование

```bash
# Режим 1: Анализ
python fractal_wheel.py "PWA-арбитраж беттинга на Индию" arbitrage analysis

# Режим 2: Синтез
python fractal_wheel.py "PWA-арбитраж беттинга на Индию" arbitrage synthesis

# Режим 3: Круги Эйлера
python fractal_wheel.py "PWA-арбитраж беттинга на Индию" arbitrage euler

# Все режимы
python fractal_wheel.py "PWA-арбитраж беттинга на Индию" arbitrage all
```

## Python API

```python
from fractal_wheel import FractalWheel

wheel = FractalWheel(center="PWA-арбитраж беттинга на Индию", domain="arbitrage")

# Режим 1: Анализ
analysis = wheel.run_analysis_mode()
print(f"Overall: {analysis.overall_percent}%")
print(f"Priority tasks: {len(analysis.priority_tasks)}")

# Режим 2: Синтез
novel_keys = wheel.run_synthesis_mode(days=7)
for key in novel_keys[:3]:
    print(f"{key.name} — compat: {key.compatibility_score:.0%}, novelty: {key.novelty_score:.0%}")

# Режим 3: Круги Эйлера
euler = wheel.run_euler_mode()
for zone in euler["green_zones"]:
    print(f"🟢 GREEN ZONE: {' ∩ '.join(zone['sectors'])} — {zone['action']}")
for zone in euler["red_zones"]:
    print(f"🔴 RED ZONE: {' ∩ '.join(zone['sectors'])} — {zone['action']}")
for zone in euler["conflicts"]:
    print(f"🟡🔴 CONFLICT: {' ∩ '.join(zone['sectors'])} — {zone['action']}")
```
