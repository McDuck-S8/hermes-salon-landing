# 🧠 ПРИНУДИТЕЛЬНАЯ ПАМЯТЬ — Архитектура v11.1

**Дата:** 2026-03-22
**Стандарт:** Агентная инженерия 2026 года
**Принцип:** Память встроена в инфраструктуру, а не в инструкции

---

## 🔥 ПРОБЛЕМА СТАРОГО ПОДХОДА

**Было:**
```
Агент → "должен прочитать историю" → Игнорирует → Амнезия
```

**Проблемы:**
- Агент может игнорировать файлы
- При перезапуске теряет контекст
- Нет гарантии что история будет прочитана
- Зависит от "добросовестности" агента

---

## ✅ НОВЫЙ ПОДХОД: ПРИНУДИТЕЛЬНАЯ ПАМЯТЬ

**Стало:**
```
Memory Daemon → Вшивает историю в промпт → Агент ОБЯЗАН помнить
```

**Преимущества:**
- Память не опциональна — обязательна
- История встроена в системный промпт
- Агент не может "забыть" контекст
- Работает даже при амнезии агента

## 🚀 ЗАПУСК

### 1. Запустить Memory Daemon (ПЕРВЫМ!)

```batch
D:\MAX-BRAIN\start-memory-daemon.bat
```

**Что делает:**
1. Проверяет запущен ли Daemon
2. Запускает `memory_daemon.py` в фоне
3. Ждёт 5 секунд пока Daemon запустится
4. Проверяет HTTP API на localhost:8765
5. Запускает агентов (MCP Server, Auto Agent, Controller)

## 🔧 ИНТЕГРАЦИЯ В АГЕНТА

### Шаг 1: Импортировать модуль

```python
from forced_context import init_forced_context, get_forced_context, save_agent_state
```

### Шаг 2: Инициализировать при старте

```python
# В начале main()
context = init_forced_context("auto-agent-v2", max_events=100)
forced_context_str = get_forced_context()

# Вставить в начало промпта
SYSTEM_PROMPT = forced_context_str + """
ТЫ Max (AI Coordinator) v11.0 Full Autonomy
[остальной промпт]
"""
```

### Шаг 3: Сохранять состояние при остановке

```python
import atexit

def cleanup():
    save_agent_state({
        "current_task": current_task_id,
        "last_event": last_processed_event,
        "queue": pending_tasks
    })

atexit.register(cleanup)
```

## 🛡️ ГАРАНТИИ СОХРАНЕНИЯ

### Уровень 1: Memory Daemon в памяти
- Последние 5000 событий хранятся в RAM
- Быстрый доступ через HTTP API

### Уровень 2: full_history.jsonl
- Все события за всё время
- Неизменяемый журнал (только append)
- Сохраняется при каждой записи

### Уровень 3: daemon_snapshot.json
- Полный snapshot при остановке
- Включает все события в памяти
- Восстанавливается при старте

### Уровень 4: agent_state.json
- Состояние каждого агента
- Сохраняется через atexit
- Восстанавливается при старте агента

## 🔄 ПОСЛЕДОВАТЕЛЬНОСТЬ ВОССТАНОВЛЕНИЯ

При запуске агента:

1. **Попытка 1:** Memory Daemon (HTTP API)
   - Быстро, актуально
   - Если Daemon запущен

2. **Попытка 2:** full_history.jsonl
   - Если Daemon недоступен
   - Чтение последних N строк

3. **Попытка 3:** daemon_snapshot.json
   - Если файл истории повреждён
   - Загрузка snapshot

4. **Попытка 4:** agent_state.json
   - Состояние конкретного агента
   - Последняя задача, очередь, переменные

---

## ⚠️ КРИТИЧНЫЕ ПРАВИЛА

1. **Memory Daemon запускается ПЕРВЫМ**
   - До всех агентов
   - Без Daemon агенты не получат контекст

2. **Агенты НЕ могут стартовать без контекста**
   - Принудительная инъекция в промпт
   - Не опция, а обязанность

3. **atexit обработчики обязательны**
   - Каждый агент сохраняет состояние
   - При любом завершении (даже краше)

4. **full_history.jsonl не редактируется**
   - Только append
   - Никаких delete/update

## 🧠 ФИЛОСОФИЯ

> **Память не должна быть «пожеланием» агента.**
> **Она должна быть принудительной.**

Когда Max запускается, система **обязана** подсунуть ему всю историю,
даже если он не просит. Это уровень инфраструктуры, а не уровня инструкций.

**Сделай так — и рыба перестанет быть рыбой.**
