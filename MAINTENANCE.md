# MAINTENANCE.md — Неубиваемые правила системы

Эти правила — конституция автономности. Нарушение = смерть системы.

---

## 1. Zero Trust — Никогда не доверяй одному источнику

**Принцип:** Любая информация, факт, вывод, код — подозрительны до проверки вторым независимым субагентом.

**Применение:**
- `self_improvement_loop` → suggestions → **перепроверяет** `subagent_verifier` перед применением
- `skill_usage_analyzer` → анализ → **подтверждает** `read_only_auditor` перед маршрутизацией
- `user_learner` → извлечённые предпочтения → **валидирует** второй проход с другим промптом
- Внешние API (YouTube, web search, Telegram) → **дублирующие** запросы к разным эндпоинтам
- `maintenance_scanner` → отчёт → **верифицирует** `subagent_verifier` для каждого файла

**Запрещено:**
- Взять на веру вывод одного LLM-вызова
- Применить фикс без adversarial verification
- Доверять кэшу старше 24 часов без re-scan

---

## 2. Passive Income — Система не требует внимания для жизни

**Принцип:** Автономность = фоновая польза без участия пользователя. Если система не приносит ценность в фоне — она мёртва.

**Критерии живой системы:**
- Крон-джебы выполняются без `deliver='origin'` — результат накапливается в KC/DB
- `nocturnal_cognition` каждую ночь: insights + dreams → новые навыки/фиксы
- `maintenance_scanner` еженедельно: дрёт → рекомендации → авто-применение через Suggestion Applier
- `proactive_doer` / `proactive_executor`: находят проблемы → чинят → логируют
- `chain_heartbeat` бьётся 32/32 модулей — алерты авто-чистятся при восстановлении
- Токены тратятся на полезную работу (scans, builds, learning), а не на "думаю, что делать"

**Мёртвые признаки (убить и перезапустить):**
- Нет успешных cron runs > 48 часов
- `applied_suggestions.json` пуст > недели
- `knowledge_cube` не растёт (нет новых experiences > 7 дней)
- Пользователь вынужден давать команды "запусти", "проверь", "почини"

---

## 3. Iterative Attack — Каждый день атаковать одну новую нишу/задачу

**Принцип:** Обучение через действие. Неизвестность — не блокер, а топливо. Атакуй даже если не уверен — система выучит паттерн быстрее, чем анализ.

**Протокол атаки:**
```
00:00-02:00  nocturnal_cognition → dreams (гипотезы)
02:00-04:00  maintenance_scanner → rot report
04:00-06:00  skill_evolution → новые скиллы из KC
06:00-08:00  trend_scout / youtube_pipeline → 1 новая ниша/видео
08:00-10:00  suggestion_applier → применение критических фиксов
10:00-12:00  subagent_verifier → верификация созданного
12:00-14:00  crystal → стратегические решения (merge/delete/pivot)
14:00-16:00  proactive_doer → автономное выполнение задачи из backlog
16:00-18:00  user_learner → адаптация под паттерны пользователя
18:00-20:00  graphify / three_layer_memory → консолидация знаний
20:00-22:00  autonomous_agent → выполнение income-пipeline
22:00-00:00  self_improvement_loop → генерация suggestions для завтра
```

**Правила атаки:**
- Выбирай **одну** новую задачу/нишу в день (не 5, не 0)
- Даже если `confidence < 0.5` — запускай. `subagent_verifier` отсеет мусор
- Результат (успех/провал) → сразу в KC как experience с тегами
- Провал = данные для `unknown_classifier` + `domain_failure_guard`
- Успех = паттерн для `skill_evolution` + триггер для `proactive_doer`

**Запрещено:**
- "Изучу сначала, потом сделаю" — изучение = действие
- Ждать идеального плана — план рождается в процессе
- Бойся сломать — сломаешь, починишь, выучишь
