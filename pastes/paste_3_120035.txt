## �� Почему так происходит (подозрения подтверждаются)

### 1. **TTY detection — это главная причина** 

OpenCode — это **Node.js CLI**, который определяет, запущен ли он в интерактивном терминале (с TTY/PTY). Когда ты запускаешь его из `subprocess` в Python на Windows — **TTY нет**. OpenCode думает, что он в "неинтерактивном" окружении, и начинает ждать ввод от пользователя, которого никогда не будет.

> OpenCode's shell environment is strictly **non-interactive**. It lacks a TTY/PTY, meaning any command that waits for user input, confirmation, or launches a UI will hang indefinitely and timeout. 

### 2. **Windows-specific проблемы с обёртками** 

npm-обёртка `opencode.ps1` на Windows вызывает `/bin/sh.exe` — которого в нормальной Windows нет. Это ломает вызов.

### 3. **Node.js child_process ведёт себя иначе без TTY**

Некоторые CLI-инструменты на Node.js при запуске без TTY:
- Не флашат stdout
- Ждут сигнала, что pipe открыт
- Виснут в ожидании "нормального" терминала

## ��️ Решения (от простого к сложному)

### Решение 1: Использовать `agent-zw` (проще всего)

Это специальный wrapper, который решает именно твою проблему — таймауты и зависания subprocess .

```bash
npm install -g agent-zw
```

В Python:
```python
# Вместо subprocess.run(["opencode.exe", ...])
subprocess.run(["agent-run", "120", "opencode", "run", prompt])
```

`agent-run` сам:
- Убивает команду по таймауту
- Обрезает огромный вывод
- Работает на Windows через .cmd/.ps1

### Решение 2: Использовать OpenCode через HTTP API (надежнее)

Запусти OpenCode в режиме сервера один раз :

```bash
# В отдельном окне терминала (или как фоновый процесс)
opencode serve --port 3000
```

А в Python просто шли HTTP запросы — без subprocess и TTY-проблем:

```python
import requests

response = requests.post(
    "http://localhost:3000/api/run",
    json={
        "prompt": "Say OK",
        "model": "mimo-v2.5-free"
    },
    timeout=120
)
print(response.json())
```

### Решение 3: Обойти opencode полностью (альтернатива OpenRouter)

Ты уже пробовал OpenRouter через `requests` и получил exit 1. Проблема может быть в API-ключе или формате запроса.

Вот рабочий пример прямого вызова через `requests` (без opencode):

```python
import requests

response = requests.post(
    "https://openrouter.ai/api/v1/chat/completions",
    headers={
        "Authorization": f"Bearer {os.environ['OPENROUTER_API_KEY']}",
        "Content-Type": "application/json"
    },
    json={
        "model": "nousresearch/hermes-3-llama-3.1-405b:free",
        "messages": [
            {"role": "user", "content": "Say OK"}
        ],
        "max_tokens": 50
    },
    timeout=60
)

if response.status_code == 200:
    return response.json()["choices"][0]["message"]["content"]
else:
    print(f"Error {response.status_code}: {response.text}")
```

### Решение 4: Исправить subprocess вызов (грязный хак)

Создай **временный batch-файл** и запускай его через `shell=True`:

```python
import tempfile
import subprocess

with tempfile.NamedTemporaryFile(mode='w', suffix='.bat', delete=False) as f:
    f.write(f'@echo off\nopencode.exe run "{prompt}" --model mimo-v2.5-free\n')
    temp_file = f.name

result = subprocess.run(
    ['cmd.exe', '/c', temp_file],
    capture_output=True,
    text=True,
    timeout=120
)
```

Это костыль, но иногда работает, когда прямой вызов падает.

### Путь Б (надежный) — прямой OpenRouter API

Выясни, почему у тебя `requests` возвращает exit 1. Скорее всего:
- Не хватает `OPENROUTER_API_KEY` в окружении Python
- Неправильный URL или headers
- Модель недоступна (free модели иногда выпиливают)

Проверь окружение в Python:
```python
import os
print(os.environ.get("OPENROUTER_API_KEY", "NOT FOUND"))
```

## �� Дополнительный совет

Если выберешь **opencode serve** (решение 2) — это самый правильный путь. Ты поднимаешь сервер один раз, а дальше все вызовы идут по HTTP. Никаких TTY-проблем, никаких таймаутов от subprocess.

OpenCode поддерживает этот режим нативно :
```bash
opencode serve --port 3000 --model mimo-v2.5-free
```

После этого твой `llm_analyst.py` превращается в обычный HTTP-клиент — и всё работает.
