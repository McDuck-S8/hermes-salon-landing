## Оценка и рекомендации для Hermes

### �� P0 — КРИТИЧЕСКИ (Нужно внедрить в первую очередь)

1. **Instructor (Type-Safe AI)** — `github.com/jxnl/instructor`
   - **Что даёт:** Гарантирует, что LLM вернёт JSON строго заданной структуры. Никаких "извините, я забыл поле".
   - **Куда встроить:** `forge.py`, `email_intake.py`, все скрипты где LLM отдаёт структурированные данные.
   - **Эффект:** Твои воркеры перестанут ломаться из-за кривых ответов модели. Forge будет генерировать код без синтаксических ошибок.

2. **Outlines (Guaranteed JSON Output)** — `github.com/dottxt-ai/outlines`
   - **Что даёт:** То же что Instructor, но на уровне токенов. Модель физически не может сгенерировать невалидный JSON.
   - **Куда встроить:** `bayesian_scorer.py`, `goal_queue.py`, `feedback_store.py`.
   - **Эффект:** 100% гарантия что структуры данных не сломаются. Особенно важно для финансовых операций.

---

### �� P1 — ВАЖНО (Внедрить во вторую очередь)

3. **LiteLLM** — `github.com/BerriAI/litellm`
   - **Что даёт:** Единый API к 100+ провайдерам. Автоматический fallback если модель упала. Отслеживание токенов и стоимости.
   - **Куда встроить:** Заменить прямые вызовы DeepSeek/OpenRouter в `autonomous_agent.py` и всех воркерах.
   - **Эффект:** Ты никогда не останешься без работающей модели. Упал DeepSeek → автоматом переключился на Groq.

4. **Langfuse (AI Observability)** — `github.com/langfuse/langfuse`
   - **Что даёт:** Трассировка каждого LLM-вызова. Видно какой промпт, какой ответ, сколько токенов, какая latency.
   - **Куда встроить:** Поверх всех LLM-вызовов в системе.
   - **Эффект:** Ты будешь видеть КАЖДЫЙ вызов модели и его стоимость. Конец "я не знаю сколько потратил".

---

### �� P2 — ПОЛЕЗНО (Внедрить когда будет время)

5. **Crawl4AI** — `github.com/unclecode/crawl4ai`
   - **Что даёт:** Веб-скрапинг оптимизированный для LLM. Отдаёт чистый markdown вместо HTML-помоев.
   - **Куда встроить:** `signal_scanner.py`, `cpa_trend_explorer.py`, `ai_tool_arbitrage_finder.py`.
   - **Эффект:** Твои разведчики будут приносить чистые структурированные данные, а не тонны мусора.

6. **Marker (PDF to Markdown)** — `github.com/VikParuchuri/marker`
   - **Что даёт:** Конвертация PDF в чистый markdown. Лучше чем PyMuPDF.
   - **Куда встроить:** В `email_intake.py` для обработки вложений, в будущий `document_intake.py`.
   - **Эффект:** Ты сможешь читать и анализировать отчёты, договоры, счета из PDF.

### �� P3 — НА БУДУЩЕЕ (Не сейчас, но иметь в виду)

7. **DSPy** — `github.com/stanfordnlp/dspy`
   - **Что даёт:** Автоматическая оптимизация промптов. Вместо ручного "промпт-инжиниринга" модель сама находит лучший промпт под задачу.
   - **Куда встроить:** В будущем — для автооптимизации всех промптов в системе.

8. **Qdrant (Vector Database)** — `github.com/qdrant/qdrant`
   - **Что даёт:** Семантический поиск по Knowledge Cube.
   - **Куда встроить:** Как апгрейд текущего FTS5 в `knowledge_cube.py`.

9. **vLLM** — `github.com/vllm-project/vllm`
   - **Что даёт:** Самый быстрый инференс опенсорсных моделей. Если будем поднимать свои модели.

10. **Ragas** — `github.com/explodinggradients/ragas`
    - **Что даёт:** Оценка качества RAG-систем. Насколько хорошо Knowledge Cube отвечает на вопросы.

11. **Chonkie (Chunking Library)** — `github.com/bhavnicksm/chonkie`
    - **Что даёт:** Разбивка больших документов на куски для эмбеддинга.

12. **Ollama** — `github.com/ollama/ollama`
    - **Что даёт:** Локальный инференс опенсорсных моделей. У тебя уже есть DeepSeek локально — Ollama не критичен.
