### 1. MemGraphRAG (новый, май 2026)

Это **новейшая исследовательская работа**, представленная на конференции KDD 2026. Она только что появилась в архиве .

*   **Что это**: Фреймворк, который решает проблему плохого качества графов, построенных из текста, когда у модели нет "общей картины". Он использует **многоагентную систему с общей памятью** (Memory-based Multi-Agent System), чтобы агенты "общались" и строили более связный и логичный граф знаний .
*   **Где найти**: Код выложен на GitHub. Ссылка прямо в аннотации статьи — `https://github.com/Yulikepython/graphrag-tutorial` .

**Как установить (исходя из структуры репозитория):**
Так как это научный проект, установка стандартная для Python-проектов:

1.  Клонируйте репозиторий:
    ```bash
    git clone https://github.com/Yulikepython/graphrag-tutorial.git
    cd graphrag-tutorial
    ```
2.  Установите зависимости (вероятнее всего, через `pip install -r requirements.txt`).

Обратите внимание: я проверил эту GitHub-ссылку из статьи, и она пока ведет на общий туториал. Возможно, код самой статьи появится там чуть позже или в другом месте (самый новый результат поиска по названию `MemGraphRAG`).

### 2. GraphRAG от Memgraph (популярное, существующее решение)

Это **уже зрелая технология** от компании Memgraph. Возможно, вы слышали о "MemoryGraphRAG" как о смешении названия "Memgraph" (база данных) и "GraphRAG" (технологии).

*   **Что это**: Промышленное решение, которое встраивает графовую базу данных прямо в RAG-пайплайн. Позволяет выполнять сложные многопрыжковые запросы и алгоритмы (PageRank, поиск сообществ) прямо внутри базы данных, что дает выигрыш в скорости и связности ответов .
*   **Особенности**:
    *   **Atomic GraphRAG**: Весь пайплайн (поиск, обогащение, ранжирование) выполняется как один атомарный Cypher-запрос .
    *   **Нативная векторная поддержка**: Не нужна отдельная векторная база данных .
    *   **Интеграции**: Работает из коробки с **LangChain** и **LlamaIndex** .

**Как установить и запустить (проще всего через Docker):**

Это официальный путь, рекомендованный Memgraph для быстрого старта .

1.  **Запустите Memgraph (ядро) через Docker**:
    ```bash
    docker run -p 7687:7687 -p 7444:7444 -p 3000:3000 memgraph/memgraph-mage
    ```
    *Это поднимет базу данных с предустановленными алгоритмами (MAGE).*

2.  **Установите Python-библиотеки**:
    Для работы с LlamaIndex (стандартный стек):
    ```bash
    pip install llama-index llama-index-graph-storage-memgraph openai
    ```

3.  **Минимальный код для подключения (Python)**:
    ```python
    from llama_index.core import PropertyGraphIndex
    from llama_index.graph_storage.memgraph import MemgraphPropertyGraphStore
    
    # Подключаемся к запущенному Docker-контейнеру
    graph_store = MemgraphPropertyGraphStore(
        uri="bolt://localhost:7687",
        user="",
        password="",
    )
    
    # Создаем индекс
    index = PropertyGraphIndex.from_documents(
        documents,
        graph_store=graph_store,
    )
    
    # Используем query engine
    query_engine = index.as_query_engine()
    response = query_engine.query("Ваш вопрос по данным")
    ```

### В чем разница?

| Характеристика | **MemGraphRAG (Новый, arXiv)** | **GraphRAG от Memgraph (Стабильный)** |
| :--- | :--- | :--- |
| **Суть** | Научный фреймворк (многоагентная память) | Промышленная база данных + RAG |
| **Статус** | Только вышел (май 2026), "pre-release" | Продакшн-релиз, много документации |
| **Установка** | `git clone` (сырой код) | `docker run` + `pip install` |
| **Сложность** | Высокая (для исследователей) | Средняя (для разработчиков) |
| **Скорость** | Зависит от реализации | Очень высокая (in-memory, нативные вектора) |
