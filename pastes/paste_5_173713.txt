## ТЕХНИЧЕСКОЕ ЗАДАНИЕ: МОДУЛЬ ОБРАБОТКИ ВИДЕО (VIDEO_LEARNER)

### 1. Назначение

Модуль предназначен для автоматического извлечения структурированных знаний из видео-контента (YouTube, Vimeo, локальные файлы) и интеграции их в онтологию агента через тактический буфер. Это частный случай внешнего импорта, но с дополнительным этапом транскрипции и семантического сжатия.

### 2. Место в архитектуре

Модуль работает как **отдельный субагент**, который:
- Запускается асинхронно по запросу пользователя или автоматически (если видео обнаружено в входящем потоке).
- Выполняется в фоне, не блокируя диалог.
- По завершении возвращает структурированный отчёт дирижёру.

**Интеграция:**
- Вызывается через `external_import.py`, если тип источника — `video_url`.
- Или напрямую через интерфейс субагентов (как `skill-doc-generator`).

---

### 3. Функциональные требования

#### 3.1. Входные данные
- URL видео (или путь к локальному файлу).
- Дополнительные параметры (опционально):
  - Язык видео (если не указан — автоопределение).
  - Тайм-коды для фокусировки (если нужно обработать только фрагмент).
  - Тип контента (лекция, туториал, обзор, интервью) — для выбора стратегии извлечения.

#### 3.2. Этапы обработки

| Этап | Действие | Используемые инструменты |
|------|----------|--------------------------|
| **1. Транскрипция** | Извлечение аудиодорожки → распознавание речи → получение текста с тайм-кодами | `yt-dlp` + `whisper` (локально) или API (AssemblyAI, OpenAI Whisper API) |
| **2. Очистка** | Удаление стоп-слов, повторов, маркеров заполнения (э-э-э, типа) | Локальный фильтр или LLM |
| **3. Семантическое сжатие** | Разбивка на смысловые блоки, выделение ключевых утверждений, инструкций, определений | LLM с промптом: «Извлеки основные концепты, практические советы, паттерны действий» |
| **4. Адаптация** | Перевод извлечённых концептов в локальные сущности (замена `email` → `telegram`, `agile` → твой процесс) | `PatternAdapter` (существующий модуль) |
| **5. Структурирование** | Формирование одного или нескольких объектов `TacticalHypothesis` с заполненными полями: | — |
| | - `title` (краткое название) | |
| | - `description` (суть) | |
| | - `trigger_conditions` (при каких условиях применять) | |
| | - `confidence` (начальный вес — 0.4, т.к. источник внешний) | |
| | - `source_type: video` | |
| | - `source_url` (ссылка) | |
| | - `tags` (извлечённые теги) | |
| **6. Запись** | Запись гипотез в `tactical_buffer.py` с TTL = 7 дней и флагом `promotion_eligible: true` | `tactical_buffer.add()` |

#### 3.3. Выходные данные
- Список созданных тактических гипотез (с идентификаторами).
- Краткая сводка: сколько концептов извлечено, сколько гипотез создано, какие ошибки возникли.
- Отчёт направляется дирижёру (в диалог) в виде структурированного сообщения.

### 4. Механизмы устойчивости и самовосстановления (решение проблемы «агент упал — всем похуй»)

| Проблема | Решение |
|----------|---------|
| **Транскрипция не удалась** (нет аудио, API недоступен) | Повтор с экспоненциальной задержкой (3 попытки). При полном провале — запись в `feedback_store` как `FAIL_CAUSE: TRANSCRIPTION_ERROR`, уведомление дирижёру. |
| **LLM-обработка зависла/упала** | Таймаут (60 секунд). При превышении — перезапуск этапа с сохранением промежуточных данных. Если падает 3 раза подряд — задача маркируется как `PARTIAL` и отправляется дирижёру с запросом на доработку. |
| **Субагент полностью крашится** | Дирижёр (autonomy_core) отслеживает heartbeat субагента. При пропаже > 2 циклов — автоматический перезапуск с теми же параметрами. Если перезапуск не помогает — создание задачи для человека (в диалог) с предложением вручную обработать видео. |
| **Условия изменились** (например, поменялся формат видео) | Модуль логирует аномалии (неожиданная структура, отсутствие ключевых блоков). Эти логи отправляются в `feedback_store`. После 3 таких аномалий модуль отправляет запрос дирижёру на обновление своих промптов или параметров (автоматическое создание новой версии). |

---

### 5. Автоматическое создание субагентов для повторяющихся задач

Мы вводим **механизм автосубагентов**:

- Если модуль видео-обработки вызывается > 5 раз в неделю — дирижёр создаёт **постоянного субагента** `video_learner_permanent`, который запускается по расписанию (например, каждые 2 часа проверяет новые видео в папке или ленте).
- Если частота использования падает ниже 2 раз в неделю — субагент переводится в режим «по запросу» (экономия ресурсов).
- Создание/удаление субагента происходит автоматически, но дирижёр уведомляет пользователя (кратким сообщением).

### 6. Интеграция с существующими модулями

| Модуль | Взаимодействие |
|--------|----------------|
| `void_response.py` | Если пользователь говорит «я посмотрел видео, но не знаю, как применить» — void_response запускает видео-обработку как Level 5 (внешний импорт) |
| `external_import.py` | Получает новый метод `import_from_video(url)`, который вызывает субагента |
| `tactical_buffer.py` | Получает гипотезы с тегом `source: video` |
| `strategic_db.py` | Гипотезы, набравшие 3 повторения и 80% успеха, промоутятся в стратегию через стандартный механизм |
| `feedback_store.py` | Логирует успехи/неудачи каждого видео-сеанса, включая ошибки транскрипции |
| `pattern_merger.py` | Может использовать видео-инсайты для обновления глобальных паттернов (если исключение побеждает) |

### 7. Пример работы (сценарий)

**Пользователь:** *«Вот видео про новую методику управления проектами: [ссылка]. Посмотри, может, пригодится.»*

**Дирижёр:** *«Принял. Запускаю видео-обработчик (delegation_id: video_abc123) в фоне. Я здесь, задавай вопросы.»*

**Субагент (фон):**
1. Скачивает и транскрибирует видео.
2. Извлекает 12 концептов.
3. Адаптирует их: заменяет «ежедневный стендап» на «утренний чат в Telegram»; «доска задач» → «Notion».
4. Создаёт 4 тактические гипотезы с confidence 0.4.
5. Записывает их в `tactical_buffer`.

**Дирижёр (по завершении):** *«Видео обработано. Извлечено 12 концептов, создано 4 гипотезы. Вот краткая сводка: [список]. Они добавлены в буфер с TTL 7 дней. Если в течение недели ты применишь их 3 раза, они станут стратегическими паттернами.»*

---

### 8. Критерии успешного завершения

- Транскрипция выполнена с качеством > 0.8 (по метрике WER).
- Извлечено минимум 3 концепта, которые прошли адаптацию.
- Все гипотезы успешно записаны в `tactical_buffer`.

При невыполнении любого критерия — возврат ошибки с детальным описанием (дирижёр получает уведомление).

---

### 9. Железные директивы для этого модуля (добавляются в ТЗ агента)

> **DIRECTIVE 0x10: VIDEO_PROCESSING**
> 1. Любое видео, переданное пользователем, обрабатывается асинхронно через субагента. Дирижёр остаётся в диалоге.
> 2. При ошибке транскрипции — 3 попытки с экспоненциальной задержкой. После 3-й — уведомление пользователя с просьбой проверить ссылку или предоставить текстовую версию.
> 3. Все извлечённые концепты адаптируются через `PatternAdapter` и записываются как тактические гипотезы с confidence = 0.4.
> 4. Если модуль вызывается > 5 раз в неделю — дирижёр создаёт постоянного субагента `video_learner_permanent` с расписанием проверки новых видео.

| 5 | Написать тестовый сценарий с YouTube-ссылкой и проверить полный цикл | Агент или пользователь |
| 6 | Зашить директиву 0x10 в ТЗ агента | Пользователь (утверждение) |
