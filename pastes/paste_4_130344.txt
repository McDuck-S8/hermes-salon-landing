## ТЗ: Полная интеграция Chain-Heartbeat во все уровни системы

**Цель:** Каждый компонент системы должен быть подключён к протоколу heartbeat. Не только демоны, но и модули, скрипты, пайплайны, внешние сервисы. Система должна знать что у неё бьётся, а что молчит — на всех уровнях матрёшки.

---

### Уровень 1: Демоны (уже сделано)

**Цепочка:** `signal_scanner → event_bus → self_improvement → suggestion_consumer → crystal`

- ✅ Каждое звено слушает upstream-соседа
- ✅ Heartbeat каждые 10 секунд
- ✅ Crystal шлёт heartbeat upstream
- ✅ Состояние в `cache/chain_heartbeat.json`

---

### Уровень 2: Модули architecture_model

**Что подключить:** Все 18 модулей из `architecture_model.json`.

**Правила:**
1. Каждый модуль при инициализации регистрируется в heartbeat-цепочке: `chain_heartbeat.register("module_name")`
2. Каждый модуль шлёт heartbeat при каждом вызове: `chain_heartbeat.beat("module_name")`
3. Crystal при каждом цикле проверяет все зарегистрированные модули. Если модуль не бился > N секунд → alert в `ALERTS.md` и задача в `goal_queue`
4. Модули-сироты (есть в модели, но нет heartbeat) → особый alert: "Модуль X не подключён к heartbeat"

**Цепочка модулей (по слоям):**
```
core → llm → knowledge → skills → telegram → tools → plugins_websrch → 
gateway → cron_tools → posting → browser_harness → plugins_selfev → 
plugins_icarus → plugins_lcm → event_system → knowledge_pipeline → 
health → crystal_base → deprecated
```

---

### Уровень 3: Пайплайны (сквозные цепочки)

**Что подключить:** Три основных пайплайна.

**Knowledge Pipeline:**
```
rss_monitor → youtube_watch → knowledge_filter → kc_populator → cube_feeder → knowledge_cube
```

**Self-Improvement Pipeline:**
```
hooks → event_evolution → verified_fixes → self_improvement_loop → suggestion_consumer → skills
```

**Action Pipeline:**
```
ghost_browser → human_behavior → account_registration → email_automation → posting → browseros_mcp
```

**Правила:**
1. Каждое звено пайплайна — это модуль или скрипт, который уже зарегистрирован в heartbeat
2. Дополнительно: пайплайн целиком имеет свой heartbeat. Если любой компонент пайплайна молчит → весь пайплайн помечается как DEGRADED
3. Если два и более компонентов молчат → пайплайн BROKEN, alert немедленно

---

### Уровень 4: Внешние сервисы

**Что подключить:**
- BrowserOS (порт 9003)
- BrowserClaw (порт 9010)
- V2RayN (прокси)
- Telegram API
- OpenRouter API
- DeepSeek Local (порт 9655)
- Cerebras API

**Правила:**
1. Каждый внешний сервис проверяется пингом каждые 60 секунд
2. Heartbeat для внешних сервисов — не просто "жив/мёртв", а с latency: `chain_heartbeat.beat("browseros", latency_ms=145)`
3. Если latency > threshold → WARNING
4. Если сервис не отвечает → alert с указанием какие пайплайны затронуты

---
