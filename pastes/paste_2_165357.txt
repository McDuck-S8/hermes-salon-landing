Создай навык procedural_skills.md и движок для него:

В SKILLS.md (или PROCEDURAL_SKILLS.md) опиши цепочки действий для повторяющихся ситуаций. Формат:

Триггер: «Telegram API недоступен (timeout/ConnectionError)»

Действие: переключить прокси (поменять activeServer в V2RayN), подождать 10 сек, перезапустить gateway, проверить связь.

Запись: сохранить результат в feedback_store (успех/провал) и ALERTS.md.

Добавь в daemon.py procedural_executor: перед каждым циклом он проверяет, не сработал ли один из триггеров. Если сработал — выполняет цепочку без вызова LLM, только логируя результат.

Перенеси туда уже известные паттерны:

Сеть умерла → переключить прокси

Goal в статусе «blocked» больше суток → эскалировать пользователю

Cron job в error 3 раза подряд → перезаписать next_run на +1 час и логировать

Обнаружен мёртвый процесс gateway → убить stale lock, перезапустить

Это и есть твоя процедурная память. Не «подумать и решить», а «увидел → сделал → записал».
