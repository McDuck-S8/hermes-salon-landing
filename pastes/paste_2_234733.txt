Ошибка `1603` (ERROR_INSTALL_FAILURE) при обновлении WSL — это проблема установщика Windows, не WSL как такового. Решим.

## �� Быстрые решения (пробуй по порядку)

### Способ 1: Установить WSL вручную через .msi

1. **Скачай последнюю версию WSL отсюда:**
   https://github.com/microsoft/WSL/releases

   Нужен файл: `wsl.2.7.7.x64.msi` (или новее)

2. **Запусти установку:** просто кликни по скачанному `.msi` файлу

3. После установки перезапусти PowerShell от администратора и проверь:
   ```powershell
   wsl --version
   ```

---

### Способ 2: Отключить антивирус/защитник временно

Ошибка 1603 часто вызывается блокировкой установщика.

```powershell
# Временно отключи Real-time protection (Пуск → Защитник Windows → Защита от вирусов → Настройки)
# Или просто выполни в PowerShell от админа:
Set-MpPreference -DisableRealtimeMonitoring $true
```

После установки WSL включи обратно:
```powershell
Set-MpPreference -DisableRealtimeMonitoring $false
```

---

### Способ 3: Очистить кэш Windows Installer

```powershell
# Остановить службу установщика
net stop msiserver

# Очистить временные файлы
del /q /s %temp%\*
del /q /s C:\Windows\Temp\*

# Перезапустить службу
net start msiserver
```

Затем повтори `wsl --update --pre-release`

---

### Способ 4: Если обновление всё равно не нужно — пропусти его

Ты можешь **не обновлять WSL**. Старый WSL (версия 1 или ранний 2) тоже работает, просто нет `autoProxy`.

**Вместо обновления используй ручную настройку прокси** (мой Способ 2 из предыдущего ответа):

```bash
# Внутри WSL:
WIN_IP=$(ip route show default | awk '{print $3}')
export http_proxy=http://$WIN_IP:7890
export https_proxy=http://$WIN_IP:7890

# Проверка
curl -I https://pypi.org
```

Если порт 7890 не твой — укажи свой (смотри в настройках прокси-клиента).

**Сделать постоянным** (добавить в `~/.bashrc` или `~/.zshrc`):
```bash
echo 'export http_proxy=http://$(ip route show default | awk '"'"'{print $3}'"'"'):7890' >> ~/.bashrc
echo 'export https_proxy=http://$(ip route show default | awk '"'"'{print $3}'"'"'):7890' >> ~/.bashrc
```

---

### Способ 5: Полная переустановка WSL (если всё совсем плохо)

```powershell
# 1. Удалить текущий WSL
wsl --unregister <имя_дистрибутива>  # например Ubuntu
# Или удалить через "Установка и удаление программ" → "Подсистема Windows для Linux"

# 2. Скачать и установить WSL вручную из .msi (см. Способ 1)

# 3. Заново установить дистрибутив
wsl --install -d Ubuntu
```
