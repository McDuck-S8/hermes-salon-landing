## FirstMate — Multi-Agent Editor Extension (VS Code)

**Суть:** Расширение для VS Code, которое создаёт команду AI-агентов для код-ревью, рефакторинга и написания кода. Агенты общаются между собой через "чат" и выполняют задачи асинхронно.

**Архитектура (ключевые компоненты):**
- **Manager Agent** — оркестратор, распределяет задачи
- **Worker Agents** — специализированные исполнители (reviewer, refactor, test-writer)
- **Agent Chat** — коммуникация между агентами в реальном времени
- **Agent Workflow** — цепочки задач: review → refactor → test → commit

**Самое ценное для нас:**

1. **Multi-Agent Collaboration Protocol**
   - Агенты общаются через структурированный чат
   - Manager разбивает задачу и раздаёт воркерам
   - Каждый воркер специализирован (один пишет, другой проверяет, третий тестирует)
   - Это именно то, что Макс пытался сделать, но провалился

2. **VS Code Integration**
   - Агенты видят диффы, могут комментить код
   - Могут создавать PR с описанием изменений
   - Могут проводить код-ревью с чек-листами

3. **Agent Workflow Engine**
   - Последовательности: `review → fix → test → merge`
   - Параллельные задачи: `test + docs` одновременно
   - Условные переходы: если тесты упали → вернуться на fix

### Что можно взять прямо сейчас (без особых напрягов)

1. **Manager-Worker Protocol (P0 — можно внедрить за час)**
   - У нас уже есть `delegate_task` и `subagent` в Hermes
   - Можно создать простой протокол: Manager-агент (наш основной мозг) → Worker-агенты (специализированные скиллы)
   - Worker'ы: `arbitrage_worker`, `content_worker`, `code_worker`, `research_worker`
   - Manager раздаёт задачи, Worker'ы отчитываются в общий чат

2. **Специализированные Worker-агенты (P1)**
   - **Reviewer Agent** — проверяет код/лендинги/контент по чек-листам
   - **Fixer Agent** — исправляет ошибки после ревью
   - **Test Agent** — прогоняет тесты и докладывает

3. **Workflow Engine (P2)**
   - Последовательности: `recon → analyse → deploy → monitor`
   - Условные переходы: если мониторинг показал ошибку → вернуться на fix
   - Параллельные задачи: `email_intake + signal_scanner + rss_reader`

---

### Что НЕ берём

- **VS Code Extension** — мы CLI-first, нам не нужен GUI
- **Полную копию архитектуры** — у нас уже есть `delegate_task`, адаптируем под себя
- **Сложные цепочки** — начнём с простого: Manager → Worker → отчёт

## План внедрения (дай агенту)

**"Ты изучил FirstMate. Помнишь Макса? Он пытался сделать такое же, но провалился. Теперь у тебя есть шанс сделать правильно.**

**Внедри Multi-Agent Collaboration Protocol в Hermes:**

1. **Создай `scripts/agent_manager.py`:**
   - Это оркестратор. Он получает задачу, разбивает её на подзадачи, раздаёт Worker-агентам.
   - Worker-агенты — это специализированные скиллы: `arbitrage_execution`, `content_pipeline`, `code_review`, `research`.
   - Протокол общения: Manager → Worker (задача) → Worker → Manager (результат) → Manager → Следующий Worker или финальный отчёт.

2. **Создай `scripts/worker_base.py`:**
   - Базовый класс для Worker-агентов.
   - Каждый Worker умеет: получить задачу, выполнить, отчитаться, записать результат в общий лог `cache/agent_team.log`.

3. **Создай первого специализированного Worker'а:**
   - `scripts/workers/review_worker.py` — агент-ревьюер. Он берёт чек-лист из Knowledge Cube и проверяет лендинг/код/контент на соответствие.

4. **Протестируй цепочку:**
   - Дай Manager'у задачу: "Сделай лендинг для салона красоты и проверь его качество".
   - Manager должен:
     - Отправить задачу `Forge` на создание лендинга.
     - Отправить результат `review_worker` на проверку.
     - Показать мне итоговый отчёт: "Лендинг создан. Оценка: 7/10. Проблемы: [список]".
