## Инструкция: Socratic Task Breakdown (Разбор задачи по косточкам)

### �� Что это?
Процесс, при котором агент рекурсивно декомпозирует задачу на подзадачи через систему вопросов, пока не останется только выполнимых «атомарных» шагов.

### �� Как работает (алгоритм):
1. **Агент получает задачу**
2. **Запускает цикл вопросов** (каждый вопрос → ответ → новый вопрос)
3. **Фиксирует «точки неопределённости»** — где не хватает информации
4. **Декомпозирует до атомарного уровня** (когда можно чётко сказать: «вот что делать»)
5. **Генерирует план выполнения**

### �� Стоп-критерии (чтобы не уходило в бесконечность):
- Задача стала **атомарной** — можно выполнить за 1-2 шага без уточнений
- **Глубина рекурсии > 5** — максимум уровней вложенности
- **Все неопределённости разрешены** — агент знает ЧТО, КАК и КАКИМИ ИНСТРУМЕНТАМИ
- **Пользователь сказал «стоп»** или «продолжай с тем, что есть»

## �� Готовые вопросные цепочки (из найденных источников)

### Вариант 1: PDCA-подход (от `pdca-scaffold`)
```
1. Какова конечная цель? (что значит "готово"?)
2. Какие входные данные нужны? (что есть сейчас?)
3. Какие инструменты/доступы есть? (чем могу пользоваться?)
4. Какие ограничения? (бюджет, время, безопасность)
5. Как проверить успех? (тесты, критерии)
```
→ После ответов переходит к PLAN → DO → CHECK → ACT 

### Вариант 2: Agent Architect Questionnaire (8 модулей)
```
1. Mission: Что агент ДОЛЖЕН сделать? (определение успеха/провала)
2. Soul: Какие ценности и границы? (что нельзя?)
3. Identity: Кто я в этой задаче? (роль)
4. Human Profile: Кто пользователь? (стиль коммуникации)
5. Operations: Как работает сессия? (режимы)
6. Tools: Чем располагаю? (доступные инструменты)
7. Memory: Что помнить? (контекст)
8. Skills: Какие навыки применить? (спецрежимы)
```
→ Генерирует 7 файлов конфигурации агента 

### Вариант 3: Recursive Decomposition (из CodeFrame Issue #421)
```
Цикл для каждого подузла:
- Это ATOMIC? (можно выполнить напрямую?)
- COMPOSITE? (требует разбивки?)
- AMBIGUOUS? (не хватает данных для решения)
  → Если AMBIGUOUS → сгенерировать вопрос пользователю
```
→ Использует классификацию на 3 исхода 

### Вариант 4: Maestro (оркестрация подзадач)
```
1. Разбить цель на подзадачи (Opus model)
2. Для каждой подзадачи: 
   - Выполнить (Haiku model)
   - Сохранить результат + память о предыдущих шагах
3. Проверить фразу "The task is complete:"
4. Иначе продолжить декомпозицию
```
→ Использует два LLM: orchestrator + executor 

### Вариант 5: Socratic Reasoning Patterns (6 паттернов)
Из Socratic-PRMBench — 6 базовых паттернов рассуждения:
| Паттерн | Что делает | Контрольные вопросы |
|---------|-----------|---------------------|
| **Transformation** | Преобразует задачу в похожую | "Какая эта задача на самом деле?" |
| **Decomposition** | Разбивает на подзадачи | "Из каких частей состоит?" |
| **Regather** | Собирает ключевую информацию | "Что нужно знать для решения?" |
| **Deduction** | Делает выводы из посылок | "Если А, то Б?" |
| **Verification** | Проверяет правильность | "А точно это правильно?" |
| **Integration** | Собирает части в целое | "Как части связаны?" |

→ Каждый паттерн имеет свои типы ошибок

## �� Рекомендуемая универсальная цепочка (синтез лучшего)

Я объединил все подходы в одну рабочую инструкцию для агента:

```markdown
## TASK BREAKDOWN PROTOCOL (Socratic Decomposition)

### PHASE 0: Init
Получил задачу: {task_description}
Глубина рекурсии: 0 (max_depth=5)
Статус: НАЧАЛО

### PHASE 1: Mission Clarity
Q1: Что конкретно должно быть результатом? (не как, а ЧТО)
Q2: По каким критериям пойму, что задача выполнена?

### PHASE 2: Context & Constraints
Q3: Какие входные данные нужны? (что есть сейчас?)
Q4: Какие ограничения? (время, доступы, безопасность)

### PHASE 3: Tool Mapping
Q5: Какие инструменты/модули доступны? (см. карту модулей Hermes)
Q6: Какие навыки/skills применить?

### PHASE 4: Decomposition Decision
Анализирую задачу:
- [ ] Это ATOMIC? (можно выполнить за 1-2 простых действия)
- [ ] Это COMPOSITE? (нужно разбить на части)
- [ ] Это AMBIGUOUS? (не хватает данных)

### PHASE 5: If AMBIGUOUS
Генерирую вопрос пользователю:
"Для выполнения задачи мне нужно знать: {specific_question}"

После ответа → возврат к PHASE 1

### PHASE 6: If COMPOSITE
Разбиваю на подзадачи:
1. {subtask_1}
2. {subtask_2}
3. {subtask_3}
Для каждой → рекурсивно запустить PHASE 1-4 (depth+1)

### PHASE 7: If ATOMIC
Записываю выполнимый шаг:
- Действие: {action}
- Инструмент: {tool}
- Выход: {expected_output}
- Время: {estimated_time}

### PHASE 8: Aggregation
Собираю все атомарные шаги в план:
- Шаг 1: {atomic_1}
- Шаг 2: {atomic_2} (зависит от шага 1)
- ...

### PHASE 9: Verification Gate
- [ ] Все неопределённости разрешены
- [ ] Все подзадачи атомарны
- [ ] План выполним имеющимися инструментами
- [ ] Глубина рекурсии не превышена

### OUTPUT: Execution Plan
{сгенерированный план действий}
```

## �� Пример работы (демонстрация)

**Входная задача:** *"Сделай бота для салона красоты"*

**Разбор:**

| Шаг | Вопрос | Ответ | Следующий вопрос |
|-----|--------|-------|------------------|
| 1 | Что должен уметь бот? | Записывать клиентов, показывать услуги, напоминать | Через какой интерфейс? |
| 2 | Через какой интерфейс? | Telegram | Какая библиотека для Telegram ботов? |
| 3 | Какая библиотека? | aiogram 3.x | Где хранить записи? |
| 4 | Где хранить? | SQLite (локально) | Нужна ли админка? |
| 5 | Нужна админка? | Да, базовую | → ATOMIC — можно делать |

**Итоговый план:**
1. Установить aiogram 3.x
2. Создать SQLite схему (клиенты, услуги, записи)
3. Написать handlers: /start, /services, /book, /my_bookings
4. Добавить напоминалки (через asyncio)
5. Сделать админ-панель (простую, /admin)
