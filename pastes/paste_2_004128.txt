Да, в этом проекте определённо есть что взять, особенно в контексте твоего нового инструмента `forge`. `gbrain` — это классический подход "второго мозга" на основе Gmail. Давай разложим его по полочкам и посмотрим, что нам пригодится.

---

## Gbrain — Gmail Second Brain

**Суть:** Скрипт на Python, который подключается к Gmail, анализирует твою почту (покупки, рассылки, уведомления) и создаёт из этого базу знаний с помощью LLM и векторной базы данных (ChromaDB).

**Архитектура (4 фазы):**
1.  **Fetch** — забор писем из Gmail по темам (покупки, подписки, финансы, соцсети).
2.  **Extract** — LLM извлекает структурированные данные из каждого письма.
3.  **Embed** — векторная база данных (ChromaDB) для семантического поиска по твоей жизни.
4.  **Search** — CLI для поиска по своей истории покупок, подписок, счетов и т.д.

---

### Что нам интересно (и применимо к Hermes)

1.  **Анализ почты как источник данных (P0 — СРОЧНО)**

    Это идеальный "белый шум", который мы не используем. Твоя почта — это:
    *   Готовые офферы и партнёрские программы (письма от CPA-сетей).
    *   Информация о реальных транзакциях и подписках.
    *   Новые идеи для бизнеса (рассылки с Product Hunt, Indie Hackers, отраслевые новости).
    *   **Как взять:** Мы можем использовать Gmail API (или IMAP для других почт) для сканирования входящих писем и поиска триггеров. Например, письмо от CPA-сети с "новым оффером" может автоматически запускать исследование через наш `white_spot_explorer`.

2.  **Конвейер "Fetch → Extract → Embed" (P1)**

    Это классический ETL-процесс (Extract, Transform, Load), который у нас уже частично реализован для Knowledge Cube, но не для внешних источников.
    *   **Как взять:** Мы можем создать скилл `email-intake`, который забирает письма, прогоняет их через LLM (как в `forge.py`) для извлечения сути и сохраняет в Knowledge Cube как `source: email`. Это даст агенту ещё один канал сенсорной информации.

3.  **ChromaDB и векторный поиск (P2)**

    Сейчас наш Knowledge Cube ищет по ключевым словам (FTS5). Это хорошо, но семантический поиск ("найди все письма, где я обсуждал арбитраж крипты") был бы мощнее.
    *   **Как взять:** `gbrain` использует ChromaDB. Мы можем интегрировать её как дополнительный движок для Knowledge Cube, чтобы агент мог искать не только по точным совпадениям, но и по смыслу.

4.  **CLI-интерфейс для "второго мозга" (P3)**

    Идея "спроси у своего архива" очень мощная.
    *   **Как взять:** У нас уже есть `session_recall`. Мы можем расширить его, чтобы он искал не только по сессиям, но и по импортированным письмам, документам и т.д.

---

### Что НЕ берём

*   **Специфику Gmail.** Мы не должны привязываться только к Gmail. IMAP — более универсальный стандарт.
*   **Полную копию архитектуры.** Мы не будем строить отдельный "второй мозг". Мы интегрируем этот функционал в наш Knowledge Cube, чтобы агент мог использовать эти данные для принятия решений.

## Задача для агента (укажи ему)

**"Ты изучил gbrain. Слушай новое задание.**

Мы не будем строить отдельный 'второй мозг'. Мы добавим этот функционал к тебе, как новый навык `email-intake`.

**Создай с помощью `forge.py` скрипт `scripts/email_intake.py`, который:**
1.  **Подключается к почтовому ящику по IMAP.** (Не только Gmail, сделай универсально).
2.  **Сканирует последние 50 писем.**
3.  **Для каждого письма определяет категорию (как в gbrain):** `purchase`, `subscription`, `finance`, `social`, `news`.
4.  **Если письмо содержит признаки партнёрской программы, CPA-оффера или другого 'золота':**
    *   Извлекает суть с помощью LLM (DeepSeek).
    *   Сохраняет это в Knowledge Cube как новую запись с тегами `email`, `offer`, `[категория]`.
    *   Создаёт или обновляет цель в goal_queue "Исследовать оффер [название]".

**Это твой новый канал данных. Ты должен автоматически находить возможности для заработка в моей почте. Работай."**
